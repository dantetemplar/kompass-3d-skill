# Примеры: запуск и проверка

Здесь описаны запуск самостоятельных макросов, регрессия галереи и измерения результата. Сами рецепты построения и галерея с изображениями находятся в [recipes.md](recipes.md). Для адаптации достаточно нужного `build`; весь стенд переносить в рабочий макрос не нужно.

## Запустить отдельный пример

Команды выполняются из каталога скилла при уже работающей API-сессии КОМПАС. Подключение не запускает программу; правила запуска сессии — в [SKILL.md](../SKILL.md).

```bash
# Построить и проверить временную деталь, затем закрыть без сохранения.
bash scripts/run.sh examples/03_holes.py

# Сохранить новый файл. Существующий файл не перезаписывается.
bash scripts/run.sh examples/03_holes.py --output ~/kompas-models/four_holes.m3d

# Сохранить исходную деталь и сборку в НОВЫЙ каталог.
bash scripts/run.sh examples/10_assembly.py --output-dir ~/kompas-models/two_blocks
```

По умолчанию документы временные: окно закроется, файлы моделей не останутся. `--output` сохраняет деталь, но не оставляет её вкладку открытой. Для сборки нужен `--output-dir`: `.a3d` ссылается на `block.m3d`, поэтому храните оба файла вместе. Чужие документы не закрываются.

В самостоятельных примерах `build` отвечает за построение, `validate` — за регрессионные проверки, `main` — за подключение, сохранение и закрытие. Некоторые дополнительные проверки находятся внутри `build`; при адаптации переносите только нужные вызовы.

### Настраиваемая пластина и кольцо

[basic_part.py](../examples/basic_part.py) позволяет выбрать форму, размеры и отверстия:

```bash
# Пластина 60 × 40 × 10 мм.
bash scripts/run.sh examples/basic_part.py plate --output ~/kompas-models/plate.m3d

# Кольцо: наружный диаметр 50 мм, отверстие 10 мм, толщина 10 мм.
bash scripts/run.sh examples/basic_part.py ring --output ~/kompas-models/ring.m3d

# Четыре сквозных отверстия Ø4 на окружности R15.
bash scripts/run.sh examples/basic_part.py plate --holes 4 --output ~/kompas-models/holes.m3d

# Те же отверстия, но глухие, глубиной 3 мм.
bash scripts/run.sh examples/basic_part.py plate --holes 4 --cut-depth 3 --output ~/kompas-models/blind.m3d
```

Все четыре команды выполнены в КОМПАС 20.10.2026. Отдельный [incremental_edit.py](../examples/incremental_edit.py) демонстрирует правку глубины и Undo/Redo с проверкой геометрии ([§29 рецептов](recipes.md)).

## Проверка размерного управления эскизом

[16_dimension_driven_sketch.py](../examples/16_dimension_driven_sketch.py) — самостоятельный общий тест: замкнутый прямоугольник с H/V, одной базовой фиксацией, линейными размерами и отверстием с размерными отступами/радиусом. Без `--output` создаёт новый сохранённый scratch-файл; с `--output` требует новый путь. Не входит в растровую галерею 01–15.

```bash
bash scripts/run.sh examples/16_dimension_driven_sketch.py
```

**Live Linux v25:** два полных успешных прогона. Нативные изменения ширины и радиуса, их восстановление и соответствующие реальные границы тела проверены; замкнутость, H/V, параллельность/перпендикулярность, отступы отверстия и fully-defined состояние сохраняются. Размеры меняются вне `BeginEdit` через `IFeature(sketch).GetVariableByName(False, True, name)`, `SetExpression(...)` и `SetValue(...)`, затем `doc3d.CompleteRebuildDocument()`. Ссылки drawing по ID нужны только для чтения геометрии в свежем fragment; старый маршрут изменения через fragment не использовать. Не проверены reopen/persistence, JPEG, независимые изменения высоты/отступов, произвольные сети и символьные зависимости. Это тест редактируемости, не измерение времени решения задания; секунды исполнения скрипта не заменяют полный wall-clock агента.

## Регрессия галереи и получение JPEG

Этот стенд нужен при изменении рецептов, примеров или проверке другой версии КОМПАС, **не перед обычным построением по готовому рецепту**.

[run_examples.py](../scripts/run_examples.py) выполняет примеры последовательно: строит → проверяет → сохраняет во временный файл → закрывает и открывает снова → повторяет проверку → получает JPEG. В конце сверяется исходный набор открытых документов. Чужие модели не меняются; КОМПАС не запускается автоматически.

```bash
# Новый каталог результатов; прежние картинки не перезаписываются.
bash scripts/run.sh scripts/run_examples.py --output-dir /tmp/kompas-examples-check

# Только выбранные примеры.
bash scripts/run.sh scripts/run_examples.py --only 02_ring 03_holes --output-dir /tmp/kompas-holes-check
```

В каталоге остаются JPEG и `verification.json` с датой, проверенными файлами, измерениями и временем. Модели проверки удаляются после закрытия документов. Для чтения и проверки JPEG скрипту нужен `pillow`; геометрию и изображения создаёт КОМПАС через `SaveAsToRasterFormat`.

**Проверено 20.10.2026 в КОМПАС-3D v25 / Linux:** все 15 примеров построены, проверены, сохранены и повторно открыты. JPEG показывает внешний вид, не доказывает геометрию. Критерии ограничены списком ниже и кодом `validate`.

### Что проверено в галерее

- **01. Пластина:** одно твёрдое тело, все шесть границ габаритов, дерево без ошибок.
- **02. Кольцо:** радиусы, центры и сквозная глубина наружной и внутренней стенок; тело и дерево.
- **03. Четыре отверстия:** все четыре цилиндрические стенки — центры, радиусы, глубина; габариты и дерево.
- **04. Вращение:** одно твёрдое тело, габариты по трём осям, дерево.
- **05. Смещённая плоскость:** тело на Z=15…20, габариты и дерево.
- **06. Три сечения:** одно твёрдое тело, габариты, дерево; не точность всей промежуточной поверхности.
- **07. Круговой массив тел:** четыре твёрдых тела, габариты каждого, центры и дерево.
- **08. Булева разность:** одно тело, цилиндрические стенки R15/R5, габариты и дерево.
- **09. Преобразование тела:** все шесть границ после преобразования, одно тело и дерево; не перенос в сборке.
- **10. Сборка:** источники, два твёрдых блока, полные матрицы, фиксация и дерево; без сопряжений.
- **11. Скругление R3 → R5:** тот же признак, четыре цилиндрические поверхности — радиус, площадь и положение у углов; конечный объём по формуле и дерево.
- **12. Фаски:** вершины и площади четырёх диагональных граней, объём 23920 мм³, тело и дерево.
- **13. Holes3D:** коллекция и параметры, стенка R5 с центром (12,7) на Z=4…10, круглое дно Z=4; объём `24000 - pi*5**2*6` и дерево.
- **14. Оболочка:** внутренние/внешние стенки, внутренние X=±28 и Y=±18, дно Z=2; ободок с контурами 60 × 40 и 56 × 36, площадь 384 мм²; объём `60*40*20 - 56*36*18 = 11712` мм³ и дерево.
- **15. Линейный массив:** шесть центров X=−20,0,20 / Y=−10,10; радиусы, глубина стенок, объём по формуле, тело и дерево.

Эти сценарии развивают идеи [Kompas3D-MCP](https://github.com/SergeySklyarov/Kompas3D-MCP/tree/8a82d6d750425bc88a87aff6b6cdf93954c91595), без переноса MCP/COM-обвязки. Статус Linux-примера устанавливается только нашим прогоном; результаты Windows/v24 его не заменяют.

## Сколько проверять в рабочем макросе

**Обычно:** статус построения/перестроения, `GetObjectError()` изменённой операции и простой наблюдаемый результат по задаче. Например, после изменения высоты — readback и нужная граница тела; после переноса — положение выбранного вхождения. Для цвета или видимости достаточно свойства/вида. Проверяйте итог логической правки, не каждый setter.

**При конкретном риске:** неизвестный вызов, новое направление выреза, смена топологии, сомнительный результат или требование к посадке/движению — добавьте адресную проверку. У отверстия это может быть сторона входа и глубина стенки, у оболочки — открытая грань и толщина. Известный `Update=True` без выреза требует проверки выреза, но не расчёта всего объёма и аудита сборки.

**Не нужны по умолчанию:** МЦХ, все грани/центры массива, полное дерево, все матрицы/сопряжения и save/reopen. Не перепроверяйте неизменившуюся геометрию и не квалифицируйте заново готовый маршрут. Для обычного сохранения достаточно статуса `SaveAs` и наличия файла.

Выберите **самую дешёвую проверку, различающую правильный результат и существенную для задачи ошибку**, и остановитесь после её успешного прохождения. Подробные `validate` галереи — регрессия, не шаблон обязательных действий.

### Геометрические измерения для диагностики и регрессии

- Скругление/фаска: поверхности у выбранных углов. Объём сам по себе не различает одинаковые углы.
- Отверстие: центр, радиус, ось, границы глубины. Глухое отверстие с обратной стороны имеет тот же объём, но другое положение дна.
- Оболочка: внутренние стенки/дно и открытая грань. Плоский ободок на месте удалённой грани нормален.
- Массив: координаты всех экземпляров, а не только `Count` и суммарный объём.

После перестроения заново получайте используемые тела/грани. Итоговые тела доступны через `ksapi.IFeature(part).GetResultBodies()`; список тел самой операции может быть пуст.

`verify_cylindrical_walls(part, expected)` из [basic_part.py](../examples/basic_part.py) проверяет простые цилиндрические стенки вдоль Z, без скруглений и разбиений. Формат записи: `(x, y, radius, zmin, zmax)`. Для кольца учитываются наружная стенка и центральное отверстие, для отверстий — каждая стенка.

При проверке сохранения/переносимости повторяйте измерения после открытия **собственной копии**, не закрывая dirty-документ пользователя. `SaveAs` не упаковывает внешние зависимости.

### Объём и единицы

Для регрессии, задачи на объём или диагностики внутренней операции объём можно получить без экспорта и материала:

```python
inertia = require(ksapi.IMassInertiaParam(part), "МЦХ детали")
inertia.SetLengthUnits(c.ksLUnMM)
require(inertia.GetLengthUnits() == c.ksLUnMM, "Фактические единицы МЦХ не мм")
require(inertia.Calculate(), "Расчёт объёма")
volume_mm3 = inertia.GetVolume()
```

Для native `IMassInertiaParam(part)` и `IFace.GetArea()` используется **`c.ksLUnMM` (1)**. Не путайте с API5-перечислением `c.ksLUMillimetres` (0): в этом интерфейсе 0 означает сантиметры и даёт объём в 1000 раз меньше. Единицы подтверждены пластиной объёмом 24000 мм³.

**Ограничение Linux v25:** после расчёта МЦХ на R3 и правки скругления на R5 повторный `Calculate()` в нашей пробе оставлял прежний объём при `IsActual() == True`, хотя поверхности уже имели R5. Поэтому в примере промежуточное R3 проверяется по граням; объём впервые считается после финального R5 и проверяется снова после открытия файла. Не распространяйте этот маршрут на произвольную правку уже измеренного документа.

Сравнивайте объём с независимо выведенной формулой и явным допуском, не с ранее наблюдённым числом. Допуск примера — не универсальный допуск ядра. Неизмеренное значение означает «не проверено», а не ноль и не успех.

## Зависимости и запуск без обёртки

Для простых примеров достаточно нативных модулей КОМПАС. Нужные сторонние пакеты объявляйте в начале самостоятельного макроса:

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["numpy", "scipy"]
# ///

import numpy as np
from scipy.optimize import root_scalar
```

`numpy` — координаты и матрицы; `scipy` — численные решения; `shapely` — плоские контуры. `cadquery-ocp` нужен только для независимой работы с B-rep/STEP, не для замены нативного построения импортом.

`ksapi`, `constants` и `constants3d` поставляются с КОМПАС, не из PyPI; `pywin32` не нужен. Оставляйте `dependencies = []`, если пакеты не используются. Не добавляйте условные импорты и запасные реализации.

```bash
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
PYTHONPATH="/opt/ascon/kompas3d-v25/Bin${PYTHONPATH:+:$PYTHONPATH}" \
uv run --script /absolute/path/to/main.py
```

`uv run --script main.py` читает PEP 723, `uv run python main.py` — нет. Для другой установки замените пути. Первый запуск пакетов может требовать сеть; следующие используют кэш. Отдельные проект, `.venv` и ручной `pip install` для одного макроса не нужны.
