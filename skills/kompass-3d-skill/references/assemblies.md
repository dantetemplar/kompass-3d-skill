# Сборки, размещения, слои и сопряжения

### Понятия: деталь, сборка, подсборка

**Деталь** — изделие из одного материала без сборочных операций: вал, втулка, крышка. Файл `.m3d`.

**Сборка** — соединённые детали, стандартные изделия и другие сборки. Файл `.a3d`. Их взаимное положение задаётся размещениями и сопряжениями.

**Подсборка** — сборка, вставленная в другую сборку. Например, предварительно собранный редуктор, который затем устанавливают в станок. Это тоже файл `.a3d`.

Такое разделение соответствует ГОСТ 2.101. Не создавайте подсборку только ради совместного скрытия деталей: для этого есть слои ([§26](#26-скрыть-группу-деталей-не-меняя-структуру-сборки)). Подсборку выделять, когда узел действительно предварительно собирается отдельно (редуктор, кассета, привод).

**Стандартные изделия** (болты, гайки, подшипники, стопорные кольца) — из библиотеки КОМПАС или готового STEP по полному обозначению (стандарт + размер), а не моделировать «на глаз». В сборке положение вхождений задавать от общих баз корпуса/рамы (плоскости, оси), а не цепочкой «деталь к предыдущей детали»: накопленные относительные смещения дают ступенчатое («лесенка») расположение и ломаются при правке параметра. После решателя сверять фактические матрицы затронутых вхождений ([§27](#27-задать-сопряжения-и-ограничить-ход)).

#### Сборки

В [§16](#16-вставить-деталь-в-сборку-и-переместить-вхождение) дана цепочка вставки внешней детали: документ `ksDocumentAssembly` → верхний компонент → `GetParts().AddFromFile(...)` → `GetPlacement()` → `UpdatePlacement(True)`. Точка входа сопряжений — `IKompasDocument3D.GetMateConstraints` ([§27](#27-задать-сопряжения-и-ограничить-ход)); перемещение ЛСК не заменяет сопряжение. В обычной правке проверять путь и изменяемое вхождение/сопряжение; полный набор листьев, матриц, ground, слоёв и mates относится к аудиту всей сборки. Движение проверять, когда оно входит в задачу. `UpdatePlacement(True)` может вернуть `False` при применённом переносе: проверять фактическую матрицу и перестроение, не один bool. Это не разрешение игнорировать произвольные ошибки.

### 16. Вставить деталь в сборку и переместить вхождение

Нужны открытая сборка `doc`, путь детали `component_path` и `require`. Для новой сборки документ создаётся как в [§2](documents.md#2-подключиться-и-создать-документ) с типом `c.ksDocumentAssembly`.

```python
from pathlib import Path

source = Path(component_path).expanduser().resolve(strict=True)
require(source.is_file() and source.suffix.lower() == ".m3d", "Нужен файл детали")
assembly = ksapi.IKompasDocument3D(doc).GetTopPart()
parts = assembly.GetParts()
before = parts.GetCount()
component = require(parts.AddFromFile(str(source), True, True), "Вставка детали")
require(parts.GetCount() == before + 1, "Число вхождений")
```

В `AddFromFile(fileName, externalFile, redraw)` первый `True` сохраняет внешнюю ссылку, второй запрашивает перерисовку. Исходный файл должен оставаться доступным. Вставка не создаёт сопряжений.

**Перенос на X=30 мм.** Нужен свободный от сопряжений компонент; проверьте его фиксацию. В существующем механизме положение обычно меняют через сопряжения ([§27](#27-задать-сопряжения-и-ограничить-ход)), а не принудительный перенос.

```python
expected = list(component.GetPlacement().GetMatrix3D())
expected[12:15] = [30.0, 0.0, 0.0]
require(component.GetPlacement().SetOrigin(30.0, 0.0, 0.0), "Перенос")
update_ok = component.UpdatePlacement(True)
require(assembly.RebuildModel(True), "Перестроение сборки")
actual = list(component.GetPlacement().GetMatrix3D())
require(len(actual) == len(expected), "Размер матрицы")
require(all(abs(a - b) < 1e-6 for a, b in zip(actual, expected)), "Положение и ориентация")
print("UpdatePlacement:", update_ok)
```

`UpdatePlacement(True)` может вернуть `False` при применённом переносе, поэтому проверяйте фактическую матрицу и результат перестроения. При несовпадении остановитесь, не повторяйте перенос вслепую. Для существующей сборки дополнительно сравните остальные вхождения, фиксацию и сопряжения ([§28](#28-изменить-существующую-сборку-без-пересоздания)).

### 26. Скрыть группу деталей, не меняя структуру сборки

Для совместного скрытия используйте слой, а не искусственную подсборку. Нужны `doc` и выбранные вхождения `components`.

```python
manager = ksapi.IKompasDocument3D(doc).GetDocument3DManager()
layers = manager.GetLayers3D()
layer = layers.GetLayer3DByName("Опоры")
if not layer:
    layer = require(layers.Add(), "Новый слой")
    layer.SetName("Опоры")
layer.SetVisible(True)
require(layer.Update(), "Слой")
for component in components:
    component.SetLayerNumber(layer.GetNumber())
    component.Update()
manager.Update()
```

Для скрытия — `layer.SetVisible(False)`, затем `layer.Update()` и `manager.Update()`; для показа — `True`. `component.GetVisibleState()` не обязательно отражает скрытие через слой; проверяйте и слой, и вид сборки.

Менеджер получайте через `GetDocument3DManager()`, не прямым приведением `IDocument3DManager(doc)`. `PartsGroupNumber` — группировка позиций спецификации, не видимость; для совместного скрытия используйте слои, не пользовательские папки.

Меняйте иерархию только ради реальной структуры монтажа. Для разворачивания подсборки нужно сохранить мировые размещения, ссылки, цвета, фиксацию, слои и сопряжения; при неединичных размещениях родителя/детей требуется композиция матриц. Удаляется вставка через `IFeature(instance).Delete()`, а не файлы деталей. Подсчёт деталей должен рекурсивно считать конечные детали, не только верхние узлы.

Не используйте `AddFromFile(..., externalFile=False)`, `CreateDocument('', c.ksDocumentAssembly, True, True)` или `MoveParts=True` как готовый способ создания подсборки: они не гарантируют требуемый тип документа и дерево сборки.

**Перенос в настоящую подсборку — отдельная рискованная операция.** В наблюдавшихся прогонах КОМПАС v25 `CreateSubAssembly` сопровождался потерей/отрывом баз сопряжений и параметров `IMateInterval`, а последующие rebuild/close/переключение документа — segfault. Это наблюдение, не доказательство единственной причины и не гарантия сбоя каждого вызова. Не считать автоматический перенос mates проверенным рецептом и не экспериментировать на пользовательской сборке.

- Сначала зафиксировать ссылки вхождений, мировые размещения и затронутые mates: обе базы, тип, ориентацию, fixed, значение, `IsUseInterval` и пределы. Отличать внутренние сопряжения группы от связей с остающимися компонентами.
- Пробу выполнять в отдельном запуске CAD, начатом пользователем или с явного согласия, на копиях всех изменяемых файлов. Одна копия корневого `.a3d` не изолирует внешние документы. Не закрывать исходный пользовательский процесс ради пробы; пути клиента/порта согласовать до запуска.
- После смены иерархии заново получить вхождения и базы в контексте их документа-владельца. Старые handles и mates вложенного вхождения не подменяют доступ к исходному документу подсборки. Проверить внешние монтажные связи, внутренние mates и интервалы, число конечных деталей и мировые размещения.
- Не предлагать удаление/пересоздание всех mates как автоматический обход. Любой маршрут миграции сначала квалифицировать на копии, включая save/reopen и требуемое движение. При оторванных базах, ошибках дерева или неудачном переносе прекратить пробу: не «лечить» цепочками rebuild, Undo и повторными `CreateSubAssembly` в том же процессе ([§34](validation.md#34-диагностический-указатель-симптом--действие)).

### 27. Задать сопряжения и ограничить ход

Сопряжение задаёт связь между вхождениями: соосность, совпадение плоскостей, расстояние, параллельность.
Нужны `doc`, выбранные объекты `base1/base2`, тип `kind`, ориентация `alignment` и значение `value` в единицах этого типа.

```python
mates = ksapi.IKompasDocument3D(doc).GetMateConstraints()
mate = require(mates.Add(kind), "Сопряжение")
mate.SetBaseObject1(base1)
mate.SetBaseObject2(base2)
mate.SetFixed(c3d.ksMFixedPart1)
mate.SetAlignment(alignment)
mate.SetParamValue(value)
require(mate.Update(), "Применение сопряжения")
require(ksapi.IFeature(mate).GetObjectError() == 0, "Ошибка сопряжения")
```

Типы: `c3d.mc_Concentric`, `mc_Coincidence`, `mc_Distance`, `mc_Parallel`. Расстояния — мм; единицы угла смотрите для конкретного типа.

**Не путайте два вида фиксации:** `mate.SetFixed(ksMFixedPart1)` выбирает сохраняемую сторону решения; `component.SetFixed(True)` закрепляет само вхождение в сборке. Для подвижного вхождения — `False`, проверка — `IsFixed()`.

Выбирайте поверхности по форме, размеру и назначению, не по номеру грани. Они доступны через `ksapi.IModelContainer(component).GetObjects(c3d.o3d_face)`. Для общей исходной системы координат можно использовать базовые плоскости `GetDefaultObject(o3d_planeXOY/XOZ/YOZ)`.

#### Проверить, куда переместил детали решатель

Чистое дерево не гарантирует правильного положения. После сопряжения сравните положение затронутых вхождений с ожидаемым; если меняется ориентация, учитывайте полную матрицу, не только перенос. Не требуется обходить все неизменившиеся вхождения сборки. Для расстояния `abs(z2-z1)` может выбрать неверную сторону. У внутренних цилиндров направление параметрической оси не определяет нужное выравнивание; для выбора ближайшего положения доступно `c3d.ksMCAlignmentClosest`. Проверяйте фактическое положение.

Предпочитать сопряжения к **общим базам** сборки (корпус, рама, именованные плоскости/оси), а не длинную цепочку «A к B, B к C»: при сдвиге одного звена остальное «лесенкой» уезжает. Каждое новое вхождение по возможности привязывать к той же системе отсчёта, что и соседние.

Для совпадающих физических торцов учитывайте ориентацию граней; общие исходные XY-базы подходят только деталям, действительно построенным в общей системе координат. Три независимых сонаправленных совпадения XY/XZ/YZ могут задать жёсткую связь, но это связь технологических баз, не модель физических контактов.

Соосность + торец оставляют вращение; параллельность поперечной плоскости запрещает проворот. Лишние упоры с обеих сторон могут переопределить механизм.

#### Ограничить осевой ход

Нужны сопряжение расстояния `distance_mate` и границы `min_value/max_value` в мм.

```python
interval = ksapi.IMateInterval(distance_mate)
interval.SetUseInterval(True)
require(interval.SetValueRange(min_value, max_value), "Границы хода")
require(distance_mate.Update(), "Применение интервала")
require(abs(interval.GetMinValue() - min_value) < 1e-6, "Нижняя граница")
require(abs(interval.GetMaxValue() - max_value) < 1e-6, "Верхняя граница")
```

**Сначала включите интервал, затем задайте диапазон.** Обратный порядок может оставить границы `0..0` без ошибки дерева. Не фиксируйте обе стороны, если решатель должен переместить одну из них.

Проверяйте реальный ход и запрещённые перемещения на копии.

После удаления сопряжений в коллекции возможны пустые места — пропускайте `None`. Не полагайтесь на сохранность заданного через `SetName` имени сопряжения; перед поиском по имени проверьте его чтением. Сопряжения не создают автоматически передачу вращения, винтовую связь, упругость или контактную динамику.

#### Тонкость выбора поверхности

Для цилиндрической поверхности с угловым первым параметром `GetMathSurface().GetPoint(0,0)` и `GetPoint(pi,0)` дают противоположные точки; их среднее лежит на оси. Если второй параметр направлен вдоль оси, разность `GetPoint(0,1)-GetPoint(0,0)` задаёт её направление. `pi` — радианы. Перед применением проверьте параметризацию поверхности.

Математическую нормаль плоскости читайте через `GetMathSurface().GetNormal`. Для ориентации физического торца отдельно учитывайте топологическую `IFace.GetNormal(0,0)`; не отождествляйте параметры её вызова с параметрами точки математической поверхности. Не навязывайте выравнивание по параметрическим осям без проверки ориентации физических граней.

### 28. Изменить существующую сборку без пересоздания

Перед правкой коротко запишите: **что добавить, изменить, удалить и сохранить неизменным**.

1. Найдите документ по полному пути ([§10](documents.md#10-открыть-существующую-модель)). Не создавайте новую сборку вместо существующей и не переоткрывайте несохранённый документ пользователя.
2. Снимите только состояние, нужное для правки: для цвета — прежний цвет, для переноса — матрицу вхождения и влияющие сопряжения, для замены детали — источник и затронутые связи. Полный снимок сборки для локального изменения не нужен.
3. Выберите минимальную правку. Цвет — только свойства отображения; видимость — слой; положение — размещение или параметр сопряжения; размер — параметр существующей операции.
4. Измените выбранные объекты. Не вставляйте заново остальные детали и не пересоздавайте все сопряжения.
5. Перестройте зависимую часть и проверьте как изменение, так и то, что должно было остаться прежним.
6. Сохраните проверенный результат. Если важна сохранность ссылок и параметров на диске, проверьте повторное открытие копии.

`RebuildModel(True)` обновляет существующую модель. Это не то же самое, что удалить сборку и построить её заново.

При изменении формы могут исчезнуть прежние грани и рёбра. Заново получите нужные поверхности и исправьте только затронутые сопряжения. Универсальная замена детали с автоматическим сохранением всех связей не подтверждена; не подменяйте её незаметным удалением и повторной вставкой.

`reference` действует в текущей сессии, не является постоянным идентификатором после открытия файла. Различайте вхождения по пути в дереве и источнику; одного имени или индекса недостаточно.

В КОМПАС записывает **один процесс**. Независимые расчёты можно выполнять отдельно, но передавайте им зафиксированные входные данные и версию задачи; устаревший результат не применяйте. Undo — [раздел Undo](documents.md#undo), повторное использование проверок — [§30](documents.md#30-не-повторять-неизменившуюся-работу).
