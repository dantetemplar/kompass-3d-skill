# Документы, владение и минимальная правка

Все командные пути указаны относительно корня скилла, а не каталога `references/`.

### Сохранение

- **Новая модель:** до создания документа проверить все выходы (`.m3d`/`.a3d`, preview и зависимости); непосредственно перед `SaveAs`/экспортом повторить проверку отсутствия. Каждой попытке выделять новый каталог, например через `tempfile.mkdtemp`; не переиспользовать путь предыдущего прогона. Нельзя заранее создавать пустой целевой файл: CAD увидит существующий путь.
- **Правка уже сохранённого собственного документа:** проверить абсолютный `GetFullPath()` и использовать `Save()`, не `SaveAs()` в тот же существующий файл. Право изменять пользовательский документ должно следовать из задачи, не из одного совпадения имени.
- **Повторный экспорт:** новый путь/каталог; прежнее изображение не удалять и не перезаписывать автоматически. Сначала проверить все выходы, чтобы не получить сохранённую модель и заблокированный запросом preview.
- Не удалять существующий файл ради обхода диалога и не отключать глобально предупреждения приложения. Если модальный диалог уже возник или вызов не завершился и исход неизвестен, не запускать второй CAD-писатель, не повторять запись вслепую и не нажимать «Да» автоматически: установить последнее действие и владельца целевого файла, сообщить блокировку. Отсутствие вызова, который *должен* показать диалог, не доказывает отсутствие любых диалогов в сессии.

Что сохранять при адаптации:

- **Нативное редактируемое дерево:** строить через KsAPI, не заменять эскизы/операции генерацией OpenSCAD/OCP → STEP. Импорт — только по запросу/согласованному исключению, явно отмечать его; успешные нативные детали не подменять. STEP/STL и изображения — только как запрошенный результат; изображение получать из КОМПАС.
- **Выбор объектов:** вхождения различать по пути/идентификатору, функциональные грани — по геометрии и назначению, не только имени или индексу. Сессионный `reference` не является постоянным ID после открытия файла. [Селекторы плоскости, цилиндра и окружности с явными допусками → §33](validation.md#33-выбрать-грань-или-окружность-по-геометрии).
- **Монтажная структура (ГОСТ 2.101):** деталь `.m3d`, сборка/подсборка `.a3d`. Подсборка — реально предварительно собираемая группа, не папка для скрытия; для видимости использовать слои ([§26](assemblies.md#26-скрыть-группу-деталей-не-меняя-структуру-сборки)). При замене детали адресно проверить затронутые сопряжения, не пересоздавать все.
- **Копии и ссылки:** для пробы связанной детали копировать файл до открытия; это не снимок dirty-документа. При модальном запросе переназначения ссылок от `SaveAs` остановить API и попросить оставить ссылки без изменения. `SaveAs` — не транзакция и не упаковка зависимостей ([§24](#24-закрыть-только-свои-временные-документы), [§30](#30-не-повторять-неизменившуюся-работу)).
- **Дорогие вычисления и reuse — если нужны:** один владелец расчёта, фиксированные входы; устаревший результат не применять. При автоматическом кэшировании учитывать содержимое и параметры, не только наличие файла. Не заводить систему хешей, benchmark или отдельный фреймворк ради простой правки ([§30](#30-не-повторять-неизменившуюся-работу)).

### Подключение: без автоматического запуска

**Использовать только `ksapi.GetKompas()` для подключения к уже запущенной пользователем API-сессии.** Если подключения нет — остановиться и дать полную Bash-команду ниже либо предложить запуск агентом и дождаться явного согласия. Запрос на построение модели или запуск макроса сам по себе не разрешает запуск КОМПАС. Не подменять подключение вызовом `OpenKompas()`.

```bash
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
LC_ALL="${LC_ALL:-C.UTF-8}" \
/opt/ascon/kompas3d-v25/Bin/kKompas -APIServer=10500
```

Пользователю давать полную команду, не наш `.sh`-файл; для другой установки заменить абсолютные пути. Не добавлять `-hidden`: окно должно быть видно. Обычное окно из меню не обязательно является API-сессией. Не закрывать и не перезапускать пользовательский процесс. Порт сервера не перенастраивает клиент `GetKompas()`.

### Существующее состояние и минимальная правка

Для существующей модели первым шагом является чтение состояния, не новый генератор. Нормализовать абсолютный путь, получить `documents = app.GetDocuments()`, затем **`documents.GetItemByFilePath(path)` до любого `Open`**. Если документ уже открыт, проверить `GetDocumentType()`/`GetFullPath()` и работать с его текущим состоянием. Не переоткрывать, не закрывать и не заменять дисковой версией dirty-документ пользователя. При отсутствии документа открыть по абсолютному пути и сразу зарегистрировать собственный handle; не определять ownership по имени вкладки или активности.

До записи достаточно короткого контракта **add / change / remove / preserve** и исходных значений нужных объектов/зависимостей. Выбрать минимальный уровень: параметр → эскиз → feature → компонент/вхождение → mates. Метаданные, appearance, слои/видимость и pose — самостоятельные маршруты без геометрической генерации. Совместное скрытие не требует подсборки ([§26](assemblies.md#26-скрыть-группу-деталей-не-меняя-структуру-сборки)); pose с mates требует solver/readback ([§27](assemblies.md#27-задать-сопряжения-и-ограничить-ход)). Смена одной детали не обосновывает повторную вставку всех компонентов и создание всех сопряжений. См. [§28](assemblies.md#28-изменить-существующую-сборку-без-пересоздания), [Undo](#undo) и [incremental_edit.py](../examples/incremental_edit.py).

Идентифицировать вхождение по пути/стабильному ID, функциональные faces — по геометрии/размеру/базе, не порядковому номеру. После rebuild, Undo/Redo и топологического изменения заново получать ссылки на тела/грани/рёбра. Даже адресная замена компонента **не гарантирует сохранение mates**: проверить пострадавшие references, адресно перепривязать ограничения и доказать preserve-контракт.

#### Владение и объём проверок

- **Один CAD-клиент во время записи.** Другие агенты могут считать геометрию локально, но не обращаться параллельно к API, переключать документы или запускать инспекторы до завершения макроса. `run.sh` только задаёт окружение, не блокирует другие клиенты. У каждого тяжёлого расчёта/import/render один владелец; отдельный orchestration framework не нужен.
- **Полный аудит — не условие каждого сохранения.** Рекурсивное дерево, все вхождения/mates — для регрессии или неясного сбоя; в обычной работе — затронутая часть ([проверки по риску](validation.md#проверки-по-риску-а-не-по-списку), [§25](validation.md#25-проверить-ошибки-дерева-и-опору-эскиза)). Motion-test — только по задаче, на собственной копии.
- Регистрировать новый документ сразу после `AddWithDefaultSettings`/нового `Open`, до `GetTopPart`. Образцы создания и проверки — в [01_plate.py](../examples/01_plate.py), `close_owned` — в [10_assembly.py](../examples/10_assembly.py) и [§24](#24-закрыть-только-свои-временные-документы); переносить нужные реализации в самостоятельный макрос, **не импортировать проектные scripts**. В `finally` закрывать только собственные временные документы; cleanup не является откатом.
- Для пробы связанной детали копировать файл **до открытия**, затем открыть копию. Это не снимок несохранённых изменений исходного документа. `SaveAs` связанной детали может открыть модальный запрос переназначения ссылок даже при read-only открытии; остановить API и попросить выбрать «Оставить ссылки без изменения». `SaveAs` — не transaction и не pack: внешние зависимости не становятся автоматически переносимыми. Если обещана переносимость, отдельно проверить ссылки и relocate/reopen на собственной копии.

#### Новый документ и верхний компонент

1. `IApplication.GetDocuments()` → `IDocuments`.
2. `IDocuments.AddWithDefaultSettings(documentType, visible)` → общий `IKompasDocument`; тип детали/сборки найти среди констант `ksDocumentPart`/`ksDocumentAssembly`.
3. `ksapi.IKompasDocument3D(doc)` → интерфейс 3D-документа.
4. `IKompasDocument3D.GetTopPart()` → `IPart`.
5. `IPart.GetModelContainer()` → `IModelContainer`.

Проверять непустые ссылки на каждом этапе. Для существующей модели сначала подтвердить тип и полный путь документа.

### Undo

Группа позволяет отменить несколько изменений **одного документа** одним шагом. Это не multi-doc/save transaction и не rollback сохранённых файлов. Рабочий пример — [incremental_edit.py](../examples/incremental_edit.py) (своя временная деталь). Итеративная правка сборки — [§28](assemblies.md#28-изменить-существующую-сборку-без-пересоздания); reuse проверок — [§30](#30-не-повторять-неизменившуюся-работу).

**До группы:** целевой active document/frame, `IsEnableUndo()`, `not IsUndoContainer()` — чужую группу не захватывать. `SetUndoContainer` / `SetEnableUndo` возвращают `None`: состояние через `Is…`, не `assert setter()`. `ClearUndo()` возвращает `bool`; историю пользователя по умолчанию не очищать и не отключать.

**Закрытие группы в `finally` — не rollback.** Exception тоже не отменяет изменения. Пустая группа не даёт права Undo предыдущей пользовательской операции: доступная команда может относиться к работе пользователя.

**Явный Undo/Redo** — только для известной завершённой изменяющей группы с понятным результатом. После неизвестного исхода вызова/обрыва — inspection, не автоматический Undo. Закрытие собственной scratch-копии без сохранения — не откат пользовательского документа.

Синхронный маршрут: `doc.GetDocumentFrame().ExecuteKompasCommand(c.ksCMEditUndo, False)` / `c.ksCMEditRedo`. Команды **57643 / 57644**; `prUndo=10211` / `prRedo=10212` — другие константы, не использовать. До команды — целевой документ/frame и `IsKompasCommandEnable` (перед самой командой, не до первой правки); после — геометрический readback и свежие topology references.

Нужны `doc3d = ksapi.IKompasDocument3D(doc)`, известная операция `operation` и положительная глубина `depth` в мм. Во время пробы никто другой не должен менять документ.

```python
require(doc3d.IsEnableUndo(), "Undo выключен")
require(not doc3d.IsUndoContainer(), "Уже открыта чужая группа")
doc3d.SetUndoContainer(True)
try:
    require(doc3d.IsUndoContainer(), "Группа не открылась")
    require(operation.GetExtrusionType(True) == c3d.etBlind, "Нужна числовая глубина")
    operation.SetDepth(True, depth)
    require(operation.Update(), "Изменение глубины")
finally:
    doc3d.SetUndoContainer(False)
require(not doc3d.IsUndoContainer(), "Группа не закрылась")
```

`SetDepth(True, depth)` меняет прямую сторону, сохраняя профиль и остальные параметры. Успех setters с `None` — чтением состояния.

Для явного Undo, когда собственная непустая группа закрыта и результат проверен:

```python
doc.SetActive()
frame = require(doc.GetDocumentFrame(), "Окно документа")
active = app.GetActiveDocument()
require(active and active.reference == doc.reference and doc.IsActive() and frame.IsActive(), "Неверный документ")
require(not doc3d.IsUndoContainer(), "Сначала закройте группу")
command = c.ksCMEditUndo  # Для Redo: c.ksCMEditRedo.
require(frame.IsKompasCommandEnable(command), "Команда недоступна")
require(frame.ExecuteKompasCommand(command, False), "Команда Undo/Redo")
```

`False` во втором аргументе — синхронное выполнение. После команды заново получить используемые объекты и проверить восстановленную геометрию; матрицы и сопряжения — только если затронуты.

Когда макрос написан, его запускают при уже открытой API-сессии ([подключение](#подключение-без-автоматического-запуска)). Путь к файлу — **абсолютный**:

```bash

# или то же окружение вручную:
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
```

### 2. Подключиться и создать документ

Этот пример создаёт **временную деталь** и закрывает её без сохранения. Поместите построение внутрь `try`, а сохранение — перед `finally`.

```python
from typing import TypeVar

import ksapi
from constants import constants as c
from constants3d import constants as c3d


T = TypeVar("T")


def require(value: T | None, message: str) -> T:
    if not value:
        raise RuntimeError(message)
    return value


app = require(ksapi.GetKompas(), "Нет запущенной API-сессии КОМПАС")
previous = app.GetActiveDocument()
doc = None
try:
    doc = require(app.GetDocuments().AddWithDefaultSettings(c.ksDocumentPart, True), "Новая деталь")
    doc3d = ksapi.IKompasDocument3D(doc)
    part = require(doc3d.GetTopPart(), "Верхний компонент")
    model = require(part.GetModelContainer(), "Операции детали")
    # Построение и проверка — здесь.
finally:
    if doc:
        require(doc.Close(c.kdDoNotSaveChanges), "Закрытие временной детали")
    if previous:
        previous.SetActive()
```

`require` проверяет результат вызова и выдаёт понятную ошибку. Не применяйте её к методам, которые ничего не возвращают: многие `Set…` возвращают `None` даже при успехе.

Для сборки используйте `c.ksDocumentAssembly`, для чертежа — `c.ksDocumentDrawing`. Для нескольких временных документов удобен список `owned` ([§24](#24-закрыть-только-свои-временные-документы)).

Если `GetKompas()` не подключился, не запускайте и не перезапускайте КОМПАС автоматически. Команда запуска и окружение Python описаны в разделе [подключения](#подключение-без-автоматического-запуска).

### 10. Открыть существующую модель

Нужны `app`, абсолютный путь `path` и список `owned` для документов, открытых этим макросом ([§24](#24-закрыть-только-свои-временные-документы)).

```python
from pathlib import Path

path = str(Path(path).expanduser().resolve(strict=True))
documents = app.GetDocuments()
doc = documents.GetItemByFilePath(path)
if not doc:
    doc = require(documents.Open(path, True, False), "Открытие модели")
    owned.append(doc)

require(str(Path(doc.GetFullPath()).resolve()) == path, "Открыт другой файл")
```

Проверьте также `doc.GetDocumentType()`: `c.ksDocumentPart` или `c.ksDocumentAssembly`.

**Сначала ищем среди открытых документов.** Уже открытая модель может содержать несохранённые изменения: нельзя заменять её дисковой версией, добавлять в `owned` или закрывать после макроса.

Если пользователь явно выбрал активное окно, допустим `app.GetActiveDocument()`, но всё равно проверьте тип и путь. Не считайте случайное активное окно нужной моделью.

### 24. Закрыть только свои временные документы

`owned` — обычный Python-список документов, созданных или открытых **этим запуском**. Это не свойство КОМПАС. У каждого документа один владелец жизненного цикла. Переданный в функцию `doc` — заимствованный: функция не закрывает и не переоткрывает его; иначе исключение до возврата нового handle оставит внешнему `finally` уже закрытый документ.

```python
owned = []
try:
    doc = require(app.GetDocuments().AddWithDefaultSettings(c.ksDocumentPart, True), "Деталь")
    owned.append(doc)  # Сразу после создания, до получения part.
    part = require(ksapi.IKompasDocument3D(doc).GetTopPart(), "Верхний компонент")
    # Построение, проверка, при необходимости сохранение.
finally:
    close_owned(owned)  # Только при работоспособной сессии; ограничения ниже.
```

Документ регистрируется сразу после создания, до получения `part`. Это позволяет закрыть его даже при локальной ошибке подготовки.

`close_owned` делает следующее:

```python
def close_owned(owned: list[ksapi.IKompasDocument]) -> None:
    # Только для работоспособной сессии; ошибка Close прекращает уборку.
    while owned:
        doc = owned.pop()  # Перед Close: неизвестный исход нельзя повторять.
        require(doc.Close(c.kdDoNotSaveChanges), "Закрытие собственного документа; не повторять")
```

Закрытие идёт в обратном порядке, **без сохранения новых изменений**. Ранее сохранённый файл остаётся на диске. Это уборка временных документов, не Undo.

Уже открытые документы пользователя в список не добавляются. Название «Деталь без имени» не доказывает, что документ ваш. Не добавляйте один handle дважды. `Close(False)` или исключение не разрешают повторный `Close`: исход может быть неизвестен.

Если нужен save/reopen, весь переход выполняет владелец: **сначала** `closing, doc = doc, None`, затем `closing.Close(...)`, затем присвоение нового `doc` из `Open`. После закрытия не использовать старые `doc3d`, `part`, коллекции, mates и грани. При нескольких документах регистрировать каждый новый handle сразу, до проверок. Не делать close/reopen внутри `migrate(doc)` с последующим `doc = migrate(doc)` у вызывающего кода.

`finally` — гарантия Python, не гарантия исправности CAD. При обрыве/таймауте, зависшем модальном вызове или подозрении на повреждение структуры не вызывать `Close`, `EndEdit`, закрытие Undo-группы, rebuild или `previous.SetActive()` из cleanup. В рискованном макросе явно отмечать неизвестный исход и пропускать CAD-cleanup; сохранить исходный traceback, не маскировать его второй ошибкой. Обычная локальная ошибка Python при работоспособной сессии не отменяет уборку своих scratch-документов. Если `Close` завершился ошибкой, не выполнять вслед за ним переключение активного документа из вложенного `finally` — это ещё один вызов в потенциально неисправный CAD.

Для перечисления документов используется `documents.GetItem(i)` с индексами **от 1 до Count**: `range(1, documents.GetCount()+1)`. Сначала получите список, потом закрывайте свои документы — не меняйте коллекцию во время индексного обхода. Путь документа — `GetFullPath()`, не `GetPathName`.

### 29. Undo/Redo

Правила группы, команды и примеры кода — в разделе [Undo](#undo). Рабочий пример — [incremental_edit.py](../examples/incremental_edit.py).

### 30. Не повторять неизменившуюся работу

Отдельно учитывайте **форму детали**, **положение в сборке**, **внешний вид** и **результаты проверок**. Изменение цвета не требует заново строить геометрию; перенос детали требует перепроверить сборочные зазоры, но не обязательно локальную форму детали.

**Чтобы повторно использовать результат, нужно знать, из чего он получен.** Запишите параметры, исходные файлы, версию кода/SDK и зависимости. Для автоматической проверки можно вычислять хеш содержимого. Наличие файла и время его изменения сами по себе не доказывают актуальность.

У проверки тоже есть условия: форма, положение, область, единицы, допуски и версия алгоритма. После изменения этих условий старый результат проверки нельзя считать актуальным.

Для дорогих проверок зазоров сначала используйте расчётные ограничения и габаритные коробки в общей системе координат, затем точную проверку нужных пар поверхностей. Быстрое отсечение должно быть консервативным. Несколько проверенных положений не доказывают отсутствие столкновений на всём ходе. Не импортируйте повторно неизменную геометрию только ради её размеров.

**Контрольное сохранение** — проверенная версия, к которой можно вернуться. Для длительного процесса храните путь, версию входных данных и последний успешный этап. Хеширование и замеры времени нужны для автоматического reuse и оптимизации, не для каждой ручной правки. Если делаете benchmark, отдельно измеряйте построение/правку, перестроение, проверку, сохранение и экспорт. Сравнивайте одинаковую правку одной исходной модели с одинаковыми проверками; число операций не равно времени.

Экспорт STEP/STL, сетка и рендер нужны только как отдельный запрошенный результат, после проверки CAD. JPEG вида — [§35](validation.md#35-сохранить-jpeg-вида). Для нового массового экспорта сначала проверьте два разных компонента: геометрию, единицы, соответствие вхождениям и ориентацию. Не угадывайте соответствие по порядку объектов. Сетку можно сохранить, если форма и настройки разбиения не изменились; положение и цвет обновляются отдельно.

Переносимый комплект требует всех внешних зависимостей. Проверьте его открытие из нового расположения без старых путей: один `SaveAs` этого не обеспечивает. Не выдавайте промежуточный или устаревший результат за окончательный.
