# КОМПАС-3D: моделирование и автоматизация на Python

Скилл для создания и изменения 3D деталей, сборок и 2D-чертежей в КОМПАС-3D с помощью Python-макросов и KsAPI. Помогает выбрать последовательность построения, создать эскизы и операции, настроить сопряжения, проверить результат и сохранить модель. При работе с существующим документом — изменить нужные элементы, сохранив остальное дерево построения.

Работа выполняется через нативный `ksapi`, поставляемый с КОМПАС-3D, без COM и `pywin32`. Ниже приведены установка, правила работы с документами, готовые рецепты и примеры, а также инструменты поиска по SDK и генерации типизированных стабов.

## Установка

Нужны установленный КОМПАС-3D с нативным KsAPI и действительной лицензией, `uv` и Bash. Для команды установки скилла нужны Node.js и npm (`npx`). Python 3.11+ может установить `uv`.

Установить скилл для Cursor:

```bash
npx skills add dantetemplar/kompass-3d-skill --skill kompass-3d-skill -g -a cursor
```

Сгенерировать документацию и стабы из установленного SDK. Выполнить из каталога установленного скилла; при другом расположении скилла или КОМПАС заменить пути:

```bash
cd ~/.cursor/skills/kompass-3d-skill
export LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export PYTHONPATH="/opt/ascon/kompas3d-v25/Bin${PYTHONPATH:+:$PYTHONPATH}"
uv run --script scripts/prepare/prepare_docs.py
uv run --script scripts/prepare/prepare_stubs.py
```

Подготовка читает официальную WebHelp (`SDK/Help/KOMPAS_SDK_ru-RU.zip`), метаданные `SDK/KsAPIC/C/Include/KsAPIC.json` и нативный KsAPI установленного КОМПАС. Генераторы не импортируют `ksapi`, не запускают КОМПАС и не используют сеть; `uv` при необходимости может загрузить Python. Для полностью офлайн-подготовки заранее установить Python 3.11+ и задать `UV_OFFLINE=1` и `UV_PYTHON_DOWNLOADS=never`. Параметры путей доступны через `--help` обоих скриптов.

Результаты находятся внутри установленного скилла:

- `.cache/kompas-sdk-docs/` — документация и поисковый индекс: `llm/pages.jsonl` — корпус, `llm/api_objects/` — страницы интерфейсов, `index.sqlite3` — поиск и навигация.
- `.cache/kompas-stubs/` — типизированные объявления с docstrings и отчёт о неизвестных типах и конфликтах. Стабы используются для анализа и подсказок; при выполнении макроса — установленные Python-модули КОМПАС.

Manifest фиксирует источники и их хеши. Эти данные генерируются локально и не входят в исходники скилла. При переносе подготовленного скилла копировать и `.cache/`. Если индекс отсутствует, `sdk.py` укажет команду подготовки, не скачивая данные. Использование справки и выбор других каталогов описаны в разделе [документации и сигнатур API](#документация-и-сигнатуры-api).

Пути `scripts/`, `examples/` и `.cache/` далее указаны относительно каталога установленного скилла. Перед первым макросом подключиться к API-сессии по разделу [подключения](#подключение-без-автоматического-запуска).

## Методика

### Порядок действий

Цель — построить или изменить модель. **Начать с подходящего примера или рецепта и адаптировать его под задачу.** Сигнатуры, docstrings и справку SDK уточнять через `sdk.py` ([документация и сигнатуры API](#документация-и-сигнатуры-api)) по мере работы.

1. Подключиться через `ksapi.GetKompas()` к существующей API-сессии. Нужный документ найти по **абсолютному пути** через `GetDocuments().GetItemByFilePath(path)`; Если он ещё открыт — открыть при помощи `Open`. Проверить тип и `GetFullPath()`. Уже открытый документ не переоткрывать, не заменять дисковой версией и не закрывать. Для новой модели создать собственный документ.
2. Выбрать дерево новой детали или минимальную правку существующей: **параметр → эскиз → операция → вхождение → сопряжения**. Не пересоздавать модель ради одного изменения. Перед сложной правкой сохранить только нужное исходное состояние.
3. Написать макрос на основе подходящего раздела [рецептов](#рецепты-для-компас-3d-на-python) или [примера](#каталог-готовых-примеров): задать размеры, геометрию и последовательность операций. Сигнатуры и docstrings уточнять через [`sdk.py doc`](#документация-и-сигнатуры-api); семантику недостающих вызовов — в SDK.
4. Выполнить макрос в КОМПАС. **Один процесс пишет в КОМПАС**; собственные временные документы и редактирование эскиза закрывать в `finally`. После смены топологии/Undo заново получать используемые грани. У выходных кортежей проверять статус; setters могут возвращать `None`.
5. Обновить затронутую модель, проверить нужный результат и сохранить в абсолютный путь, если это входит в задачу. Не перезаписывать чужие файлы без основания; достаточно статуса сохранения и наличия файла, **без обязательного reopen**. Сообщить результат и закончить.

Для знакомой операции обычно достаточно рабочего кода. Примеры полезны при выборе реализации; `sdk.py` и SDK — при вопросах о сигнатуре, маршалинге, поведении или ошибке. Читать столько, сколько помогает следующему действию, без обязательного обхода всех источников. Рискованный неизвестный режим сначала опробовать в собственном временном документе; после обрыва API не повторять запись вслепую.

### Как спланировать модель детали

**От общего к частному:** разобрать форму → выбрать основание и базы → построить основной объём → добавить/удалить материал → повторить элементы → обработать края. Это методика выбора дерева, не единственный правильный порядок. Для существующей модели сохранить её замысел и изменить нужную ветвь, а не проектировать всё заново.

Перед кодом кратко определить:

1. **Геометрия и назначение.** Выделить основные объёмы, отверстия, пазы, посадки и симметрии. По чертежу учитывать виды, разрезы и размеры; не угадывать скрытую форму по одной проекции. Существенные недостающие размеры уточнять, допустимые предположения обозначать.
2. **Основание.** Выбрать конструктивно главный элемент, от которого удобно добавлять/вычитать материал и задавать остальные размеры. Самый крупный объём — частый, но не обязательный выбор.
3. **Базы и ориентация.** Разместить начало координат, главную ось и плоскость первого эскиза по симметрии, монтажным/измерительным базам и удобству дальнейших операций. Предпочитать устойчивые базовые/смещённые плоскости и оси; грань использовать, когда нужна именно связь с ней. Не опирать важные элементы на случайные рёбра скруглений.
4. **Замысел изменений (design intent).** Решить, что должно оставаться соосным, симметричным, равноудалённым или на заданном расстоянии от края. Отверстие «по центру» и «в 10 мм от края» — разные зависимости. По возможности определять эскизы размерами и геометрическими связями без переопределения. Python-переменная и координаты, вычисленные генератором, сами по себе не создают редактируемую зависимость внутри КОМПАС; не выдавать их за полную параметризацию.
5. **Основной объём и конструктивные элементы.** Выбрать операции по форме ниже; затем добавить выступы, рёбра, отверстия и вырезы. Разделять элементы по смыслу и будущим изменениям, а не объединять всё в один сложный эскиз ради меньшего числа операций.
6. **Повторения и завершение.** Использовать массивы/зеркало для конструктивно связанных повторов. Мелкие фаски и скругления обычно делать поздно, чтобы не усложнять опоры. Оболочку, уклоны и формообразующие скругления ставить там, где они правильно задают толщину и переходы; правило «все скругления в конце» не абсолютное.
7. **Результат.** Проверить успешность построения и один итоговый признак, например объём из условия. Само требование параметрической модели не означает обязательного теста изменения размеров; он нужен только по отдельному запросу или при диагностике.

### Как выбрать операцию

- Постоянное сечение вдоль прямой — **выдавливание**; осесимметричный профиль — **вращение**.
- Карман, паз, простой вырез — **вырез выдавливанием**; кольцевая канавка — **вырез вращением**. Для отверстия с собственными параметрами/типом — родная операция **Holes3D** (§31 рецептов).
- Профиль вдоль траектории — **кинематическая операция**; переход между несколькими профилями — **элемент по сечениям**.
- Регулярный повтор — **массив операций**; симметричный элемент — **зеркало**. Повтор тел выбирать только когда нужны отдельные тела, не вместо массива отверстий.
- Тонкостенная полость — **оболочка**; скосы и плавные переходы краёв — **фаски/скругления**.

Для нетривиальной новой детали достаточно одной строки предполагаемого дерева, без отдельного документа и согласования каждого шага. Например, фланец: **вращение ступенчатого профиля (основание + ступица) → центральное отверстие → одно крепёжное отверстие → круговой массив → фаски**. Два выдавливания вместо вращения тоже допустимы: выбирать по удобству размеров и редактирования, не минимизировать число операций любой ценой. Для простой правки отдельный план не нужен.

### Размерная модель, а не замороженный чертёж

Если требуется параметрическая редактируемая модель, задавать конструктивные зависимости **внутри КОМПАС**: совпадение концов, горизонтальность/вертикальность, касательность, равенство, симметрию и управляющие размеры. Фиксировать только необходимую базу; не фиксировать оба конца каждого отрезка ради `WellConstrained`. Нулевые степени свободы, Python-переменные и точные начальные координаты не доказывают сохранение замысла при редактировании. Декоративный размер без управляющей связи тоже не доказательство. `IDimensionText.SetNominalValue()` меняет отображаемый текст, а не геометрию; не использовать его как механизм параметрического изменения.

Параметрическую модель строить с нативными связями и размерами, но **не добавлять пробные изменения размеров в каждое решение**. Тест изменения/восстановления нужен только по отдельному запросу на проверку редактируемости или при диагностике конкретной проблемы. Тогда менять нативный размер и проверять фактическую геометрию; перегенерация профиля Python-кодом не считается этим тестом. Неудачу API не маскировать тотальной фиксацией. Не заявлять проведённый тест редактируемости, если его не выполняли.

Общий пример: [16_dimension_driven_sketch.py](examples/16_dimension_driven_sketch.py), [маршрут API](#размерные-зависимости-эскиза). Существующий размер менять **вне `BeginEdit`**: `ksapi.IFeature(sketch).GetVariableByName(False, True, name)` → `SetExpression(...)` и `SetValue(...)` → `doc3d.CompleteRebuildDocument()` → проверить B-rep. Не использовать `view.GetDimensionVariable(dim)` временного 2D-фрагмента для изменения геометрии: новое значение и успешный rebuild не гарантируют её изменения. `UpdateVariables()` применяет внешние переменные, не является универсальным solver-вызовом. Объекты drawing после нового `BeginEdit` получать заново через `fragment.GetObjectById(id)`. Наличие переменной с новым значением без изменения геометрии не считать успехом. Это правило одинаково для линейных и радиальных размеров: не возвращаться к маршруту через fragment и не подбирать цепочки rebuild. При отказе маршрута через `IFeature` сохранить текущую деталь и сообщить конкретное расхождение, а не переключаться на другой размер ради успешного теста.

### Координаты эскиза и направление операции

Не отождествлять имена плоскостей с привычной экранной ориентацией. Для незнакомой опоры получить `ISketch.GetPoint3D(u, v, 0, 0, 0)` для `(0,0)`, `(1,0)`, `(0,1)`, проверить статус каждого выходного кортежа и вывести локальные оси/нормаль. Для наклонной грани использовать проекцию и обратное преобразование. Это короткая проверка системы координат, не повод строить отдельную пробную деталь для каждого знакомого эскиза.

Направление операции и активная сторона глубины — разные настройки: при обратном направлении настраивать соответствующую сторону `SetSideParameters(False, ...)`. Для нового маршрута подтвердить вход, дно/выход по реальным поверхностям; `Update()` и значение глубины в setter не доказывают сквозной вырез. Не делать обязательным `GetSideParameters()`, если его output-marshalling не работает в нативном KsAPI: это ограничение binding, а не основание пропустить геометрическую проверку.

### Проверки по риску, а не по списку

**Обычное решение задачи:** достаточно успешного построения, отсутствия ошибок операций и сравнения объёма с эталоном, если он дан. Не добавлять обход граней/рёбер/вершин, аудит связей размеров, проверку всех габаритов, пробные изменения размеров и повторное открытие файла. Для локальной правки проверить только её результат. Проверять по завершении логического действия, а не после каждого setter.

**Расширенные проверки полезны**, когда есть неизвестный маршрут API, существенно другая геометрия, ошибка/подозрительный результат, смена топологии с зависимостями или требование к посадке/движению. Проверять именно затронутые поверхности, связи или зазор. При известной неоднозначности bool из рецепта читать фактический результат; это не разрешение игнорировать произвольные ошибки. Успешный `Update()` сам по себе не доказывает нужную форму.

**Регрессия рецептов:** подробные `validate` предназначены для разработки и повторной проверки примеров. Расчёт объёма, полный аудит, save/reopen и испытание всего хода обычно избыточны для локальной правки, но могут быть полезны для диагностики или приёмки. Проверку повторного открытия выполнять на собственной копии.

Проверки соразмерять задаче; неизменившиеся части обычно не требуют повторных измерений. Экспорт, рендер и замеры производительности добавлять, когда они нужны для результата. Защита пользовательских документов и безопасность Undo сохраняются независимо от объёма проверок.

### Сохранение

- **Новая модель:** до создания документа проверить все выходы (`.m3d`/`.a3d`, preview и зависимости); непосредственно перед `SaveAs`/экспортом повторить проверку отсутствия. Каждой попытке выделять новый каталог, например через `tempfile.mkdtemp`; не переиспользовать путь предыдущего прогона. Нельзя заранее создавать пустой целевой файл: CAD увидит существующий путь.
- **Правка уже сохранённого собственного документа:** проверить абсолютный `GetFullPath()` и использовать `Save()`, не `SaveAs()` в тот же существующий файл. Право изменять пользовательский документ должно следовать из задачи, не из одного совпадения имени.
- **Повторный экспорт:** новый путь/каталог; прежнее изображение не удалять и не перезаписывать автоматически. Сначала проверить все выходы, чтобы не получить сохранённую модель и заблокированный запросом preview.
- Не удалять существующий файл ради обхода диалога и не отключать глобально предупреждения приложения. Если модальный диалог уже возник или вызов не завершился и исход неизвестен, не запускать второй CAD-писатель, не повторять запись вслепую и не нажимать «Да» автоматически: установить последнее действие и владельца целевого файла, сообщить блокировку. Отсутствие вызова, который *должен* показать диалог, не доказывает отсутствие любых диалогов в сессии.

Что сохранять при адаптации:

- **Нативное редактируемое дерево:** строить через KsAPI, не заменять эскизы/операции генерацией OpenSCAD/OCP → STEP. Импорт — только по запросу/согласованному исключению, явно отмечать его; успешные нативные детали не подменять. STEP/STL и изображения — только как запрошенный результат; изображение получать из КОМПАС.
- **Выбор объектов:** вхождения различать по пути/идентификатору, функциональные грани — по геометрии и назначению, не только имени или индексу. Сессионный `reference` не является постоянным ID после открытия файла. [Селекторы плоскости, цилиндра и окружности с явными допусками → §33](#33-выбрать-грань-или-окружность-по-геометрии).
- **Монтажная структура (ГОСТ 2.101):** деталь `.m3d`, сборка/подсборка `.a3d`. Подсборка — реально предварительно собираемая группа, не папка для скрытия; для видимости использовать слои (§26). При замене детали адресно проверить затронутые сопряжения, не пересоздавать все.
- **Копии и ссылки:** для пробы связанной детали копировать файл до открытия; это не снимок dirty-документа. При модальном запросе переназначения ссылок от `SaveAs` остановить API и попросить оставить ссылки без изменения. `SaveAs` — не транзакция и не упаковка зависимостей (§24, §30).
- **Дорогие вычисления и reuse — если нужны:** один владелец расчёта, фиксированные входы; устаревший результат не применять. При автоматическом кэшировании учитывать содержимое и параметры, не только наличие файла. Не заводить систему хешей, benchmark или отдельный фреймворк ради простой правки (§30).

Рецепты: понятия деталь/сборка/подсборка — раздел «Понятия»; основа/подключение/эскиз — §1–3; контуры/выдавливание — §4–6; повтор координат/Безье — §7–8; контроль/существующий документ/2D — §9–11; вращение/смещённая плоскость — §12–13; фаска/скругление/feature-массив/сборка — §14–16; дуга `IArc`/касательное сопряжение с обрезкой — §17–18; монтажная структура — §26; сборочные сопряжения, знаки расстояний и ограниченный осевой ход — §27; **итеративная правка и reuse — [§§28, 30](#28-изменить-существующую-сборку-без-пересоздания); Undo — [раздел Undo](#undo)**. Родное отверстие Holes3D — §31; открытая коробка оболочкой IShell — §32. В каталоге есть самостоятельные примеры 11–15 с аналитическим объёмом и проверками положения поверхностей. Статус проверки смотреть в выбранном разделе: заготовку не выдавать за выполненное построение.

При ошибке, подозрительной геометрии или конкретном неизвестном вызове — адресная диагностика ниже. Не перестраивать всю модель ради исправления, которое можно проверить на одном элементе. Выборка точек не доказывает непрерывную точность кривой.

## Undo

Группа позволяет отменить несколько изменений **одного документа** одним шагом. Это не multi-doc/save transaction и не rollback сохранённых файлов. Рабочий пример — [incremental_edit.py](examples/incremental_edit.py) (своя временная деталь). Итеративная правка сборки — [§28](#28-изменить-существующую-сборку-без-пересоздания); reuse проверок — [§30](#30-не-повторять-неизменившуюся-работу).

**До группы:** целевой active document/frame, `IsEnableUndo()`, `not IsUndoContainer()` — чужую группу не захватывать. `SetUndoContainer` / `SetEnableUndo` возвращают `None`: состояние через `Is…`, не `assert setter()`. `ClearUndo()` возвращает `bool`; историю пользователя по умолчанию не очищать и не отключать.

**Закрытие группы в `finally` — не rollback.** Exception тоже не отменяет изменения. Пустая группа не даёт права Undo предыдущей пользовательской операции: доступная команда может относиться к работе пользователя.

**Явный Undo/Redo** — только для известной завершённой изменяющей группы с понятным результатом. После неизвестного исхода вызова/обрыва — inspection, не автоматический Undo. Закрытие собственной scratch-копии без сохранения — не откат пользовательского документа.

Синхронный маршрут: `doc.GetDocumentFrame().ExecuteKompasCommand(c.ksCMEditUndo, False)` / `c.ksCMEditRedo`. Команды **57643 / 57644**; `prUndo=10211` / `prRedo=10212` — другие константы, не использовать. До команды — целевой документ/frame и `IsKompasCommandEnable` (перед самой командой, не до первой правки); после — геометрический readback и свежие topology references.

Нужны `doc3d = ksapi.IKompasDocument3D(doc)`, известная операция `operation` и положительная глубина `depth` в мм. Во время пробы никто другой не должен менять документ.

```python
require(doc3d.IsEnableUndo(), "Undo выключен")
require(not doc3d.IsUndoContainer(), "Уже открыта чужая группа")
doc3d.SetUndoContainer(True)
try:
    require(doc3d.IsUndoContainer(), "Группа не открылась")
    require(operation.GetExtrusionType(True) == c3d.etBlind, "Нужна числовая глубина")
    operation.SetDepth(True, depth)
    require(operation.Update(), "Изменение глубины")
finally:
    doc3d.SetUndoContainer(False)
require(not doc3d.IsUndoContainer(), "Группа не закрылась")
```

`SetDepth(True, depth)` меняет прямую сторону, сохраняя профиль и остальные параметры. Успех setters с `None` — чтением состояния.

Для явного Undo, когда собственная непустая группа закрыта и результат проверен:

```python
doc.SetActive()
frame = require(doc.GetDocumentFrame(), "Окно документа")
active = app.GetActiveDocument()
require(active and active.reference == doc.reference and doc.IsActive() and frame.IsActive(), "Неверный документ")
require(not doc3d.IsUndoContainer(), "Сначала закройте группу")
command = c.ksCMEditUndo  # Для Redo: c.ksCMEditRedo.
require(frame.IsKompasCommandEnable(command), "Команда недоступна")
require(frame.ExecuteKompasCommand(command, False), "Команда Undo/Redo")
```

`False` во втором аргументе — синхронное выполнение. После команды заново получить используемые объекты и проверить восстановленную геометрию; матрицы и сопряжения — только если затронуты.

## Подключение: без автоматического запуска

**Использовать только `ksapi.GetKompas()` для подключения к уже запущенной пользователем API-сессии.** Если подключения нет — остановиться и дать полную Bash-команду ниже либо предложить запуск агентом и дождаться явного согласия. Запрос на построение модели или запуск макроса сам по себе не разрешает запуск КОМПАС. Не подменять подключение вызовом `OpenKompas()`.

```bash

LC_ALL="${LC_ALL:-C.UTF-8}" \
```

Пользователю давать полную команду, не наш `.sh`-файл; для другой установки заменить абсолютные пути. Не добавлять `-hidden`: окно должно быть видно. Обычное окно из меню не обязательно является API-сессией. Не закрывать и не перезапускать пользовательский процесс. Порт сервера не перенастраивает клиент `GetKompas()`.

## Подготовка и запуск макроса

Новый макрос должен быть самостоятельным: копировать нужные функции примера, не импортировать их из каталога скилла. У функций указывать типы всех аргументов и возвращаемого значения; для объектов API использовать конкретные интерфейсы `ksapi`. Типизацию `validate` и габаритов (`Bounds`) можно опустить. В начале объявить только используемые зависимости:

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["numpy", "scipy"]
# ///

import ksapi
import numpy as np
from scipy.optimize import root_scalar
```

Для простой геометрии достаточно `dependencies = []`. `numpy` — координаты и вращения; `scipy` — сплайны и численные решения; `shapely` — проверка плоских контуров; `cadquery-ocp` (импорт `OCP`) — независимый B-rep/STEP-контроль, только если нужен. `ksapi` и константы поставляются с КОМПАС, не устанавливать их из PyPI. Не писать условные импорты, не создавать проект/`.venv` и не запускать `pip install` ради одного макроса.

```bash
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
PYTHONPATH="/opt/ascon/kompas3d-v25/Bin${PYTHONPATH:+:$PYTHONPATH}" \
uv run --script /absolute/path/to/main.py аргументы
```

`uv run --script main.py` и `uv run main.py` обрабатывают PEP 723, **`uv run python main.py` — нет**. Первый запуск новых пакетов может требовать сеть; следующие используют кэш. Необязательный `bash scripts/run.sh /absolute/path/to/main.py аргументы` задаёт то же окружение, сохраняет текущий каталог и не запускает КОМПАС. Это не песочница.

```bash
uv run --script scripts/sdk.py verify --brief ISketch.BeginEdit IExtrusion.SetSideParameters
```

- `local` — поиск имён интерфейсов и методов; `constants` — поиск констант по имени или русскому комментарию.
- `inspect` — объявления нативного KsAPI. Для класса показаны сигнатуры, включая унаследованные; `--match` фильтрует методы по имени. Для метода `--source` добавляет тело: это позволяет уточнить преобразования массивов, нативных ссылок и выходных параметров.
- `verify` — только наличие перечисленных символов; `--brief` оставляет счётчики и отсутствующие имена. Корректность макроса и работоспособность API не проверяются.

В `inspect` поле `symbol` указывает фактический класс-владелец, `path`/`line`/`end_line` — расположение объявления. `constructed_interfaces` перечисляет конструкторы в теле, но не гарантирует тип результата; `returns_value` означает наличие `return` со значением, а не успешность операции. Сигнатуры включают `self`, который при вызове связанного метода не передаётся. `ksapi.IInterface(obj)` запрашивает другой интерфейс того же объекта, а не дочерний объект.

Сигнатуры, docstrings, поиск по SDK и чтение нативного KsAPI — в разделе [документации и сигнатур API](#документация-и-сигнатуры-api).

## Нативный KsAPI: справочник рабочего процесса

Это справочник для диагностики и неподдержанных примерами случаев. Для обычной задачи использовать известный код и приступать к выполнению; если реализации не хватает — открыть нужный [рецепт](#рецепты-для-компас-3d-на-python). Известный маршрут использовать без повторного исследования. Чтение всего справочника, scratch-проба, инспекция SDK и загрузка базы не являются обязательным прологом. Объём проверок — по риску, как в разделе [проверок](#проверки-по-риску-а-не-по-списку).

### Отличия от Windows-справки

- Документированный `IPart7` в нативном KsAPI представлен классом `IPart`: это видно в теле `IKompasDocument3D.GetTopPart`. Не заменять все имена с суффиксом `7` автоматически.
- Свойство `ModelContainer` представлено `IPart.GetModelContainer()`. Другие свойства могут иметь `Get…`, `Set…`, `Is…` и аргументы — смотреть реальное объявление.
- `ksapi.IKompasDocument3D(doc)` или `ksapi.IDrawingContainer(view)` запрашивает другой интерфейс того же объекта. Вызов `GetTopPart()` или `GetModelContainer()` получает другой объект. Эти переходы не взаимозаменяемы.
- `GetReference(None)` превращается в нулевую ссылку. Это реализация маршалинга, а не разрешение передавать `None` в любой аргумент.
- Методы с выходными параметрами могут требовать начальных значений и возвращать кортеж. Например, локальный `ISketch.GetPoint3D` требует `xIn, yIn, xOut, yOut, zOut` и возвращает статус вместе с координатами.
- Константы обоих модулей находятся в классе `constants`: обычные импорты — `from constants import constants as c` и `from constants3d import constants as c3d`.

### Существующее состояние и минимальная правка

Для существующей модели первым шагом является чтение состояния, не новый генератор. Нормализовать абсолютный путь, получить `documents = app.GetDocuments()`, затем **`documents.GetItemByFilePath(path)` до любого `Open`**. Если документ уже открыт, проверить `GetDocumentType()`/`GetFullPath()` и работать с его текущим состоянием. Не переоткрывать, не закрывать и не заменять дисковой версией dirty-документ пользователя. При отсутствии документа открыть по абсолютному пути и сразу зарегистрировать собственный handle; не определять ownership по имени вкладки или активности.

До записи достаточно короткого контракта **add / change / remove / preserve** и исходных значений нужных объектов/зависимостей. Выбрать минимальный уровень: параметр → эскиз → feature → компонент/вхождение → mates. Метаданные, appearance, слои/видимость и pose — самостоятельные маршруты без геометрической генерации. Совместное скрытие не требует подсборки (§26); pose с mates требует solver/readback (§27). Смена одной детали не обосновывает повторную вставку всех компонентов и создание всех сопряжений. См. [§28](#28-изменить-существующую-сборку-без-пересоздания), [Undo](#undo) и [incremental_edit.py](examples/incremental_edit.py).

Идентифицировать вхождение по пути/стабильному ID, функциональные faces — по геометрии/размеру/базе, не порядковому номеру. После rebuild, Undo/Redo и топологического изменения заново получать ссылки на тела/грани/рёбра. Даже адресная замена компонента **не гарантирует сохранение mates**: проверить пострадавшие references, адресно перепривязать ограничения и доказать preserve-контракт.

#### Владение, reuse и проверки

- **Один CAD writer.** У каждого тяжёлого расчёта/import/render один владелец; передать frozen inputs и revision, не запускать дублирующий расчёт. Superseded результаты не применять. Явного ownership и короткой записи этапов достаточно, отдельный orchestration framework не нужен.
- **Reuse по semantic hash**, не `exists()`/mtime: исходники, параметры, recipe/backend/SDK и зависимости. Геометрия, placement, проверка и presentation имеют отдельные ключи; результат проверки также зависит от допусков, предпосылок, алгоритма и его версии. Инвалидировать затронутые зависимости, не всё дерево по умолчанию.
- После логической правки проверить статус, ошибку затронутой операции и простой признак нужного результата. Функциональные поверхности, зазоры и зависимости проверять адресно при соответствующем риске/требовании; для цвета и видимости геометрический контроль не нужен. Дорогую проверку начинать с аналитики/AABB, затем переходить к нужным парам/faces и exact narrowphase. Не импортировать одну геометрию повторно ради metadata.
- **Полный аудит — не условие каждого сохранения.** Рекурсивное дерево, число листьев сборки, матрицы всех вхождений, ground, слои и все живые mates нужны для регрессии, диагностики с неясной областью сбоя или явной приёмки всей сборки. В обычной работе проверять затронутую часть. Motion-test — только по задаче/риску; выполнять на собственной копии, если он нарушает pose пользователя.
- Регистрировать новый документ сразу после `AddWithDefaultSettings`/нового `Open`, до `GetTopPart`. `new_part(app, name, owned=owned)`, `close_owned(owned)` и `feature_errors(part)` в [basic_part.py](examples/basic_part.py) служат основой; переносить нужные реализации в самостоятельный макрос, **не импортировать проектные scripts**. В `finally` закрывать только собственные временные документы; cleanup не является откатом.
- Для пробы связанной детали копировать файл **до открытия**, затем открыть копию. Это не снимок несохранённых изменений исходного документа. `SaveAs` связанной детали может открыть модальный запрос переназначения ссылок даже при read-only открытии; остановить API и попросить выбрать «Оставить ссылки без изменения». `SaveAs` — не transaction и не pack: внешние зависимости не становятся автоматически переносимыми. Если обещана переносимость, отдельно проверить ссылки и relocate/reopen на собственной копии.

### Последовательности исследования

#### Новый документ и верхний компонент

1. `IApplication.GetDocuments()` → `IDocuments`.
2. `IDocuments.AddWithDefaultSettings(documentType, visible)` → общий `IKompasDocument`; тип детали/сборки найти среди констант `ksDocumentPart`/`ksDocumentAssembly`.
3. `ksapi.IKompasDocument3D(doc)` → интерфейс 3D-документа.
4. `IKompasDocument3D.GetTopPart()` → `IPart`.
5. `IPart.GetModelContainer()` → `IModelContainer`.

Проверять непустые ссылки на каждом этапе. Для существующей модели сначала подтвердить тип и полный путь документа.

#### Эскиз и геометрия

1. `IPart.GetDefaultObject(objectType)` — получить опорную геометрию; для базовой плоскости найти `o3d_planeXOY`, `o3d_planeXOZ` или `o3d_planeYOZ`.
2. `IModelContainer.GetSketchs()` → `ISketchs`; `ISketchs.Add()` → `ISketch`.
3. `ISketch.SetPlane(plane)`, затем `ISketch.BeginEdit(readOnly)` → `IFragmentDocument`.
4. Проверить у `IFragmentDocument` доступ к видам; получить активный `IView` и запросить `IDrawingContainer`.
5. Получить нужные коллекции и создать контур. Проверить параметры геометрии, `Update()` и замкнутость контура.
6. Завершить `ISketch.EndEdit()` до создания операции. В макросе обеспечить завершение редактирования при исключении через `finally`.

Искать страницы `isketch_beginedit`, `isketch_endedit`, затем методы конкретной геометрии. Для новых плоскостей, проекций и пространственных кривых исследовать отдельные интерфейсы, не подменять их базовыми плоскостями.

#### Выдавливание и вырез

1. Прочитать `iextrusions_add`: разрешены `o3d_bossExtrusion` и `o3d_cutExtrusion`.
2. `IModelContainer.GetExtrusions()` → `IExtrusions`; `IExtrusions.Add(extrusionType)` → `IExtrusion`.
3. В нативном KsAPI `IExtrusion.SetProfiles(profiles)` принимает коллекцию ссылок через `ToObjectReferenceVector`. Документационный поиск по слову `Profile` может показывать другой интерфейс, например `IExtrusion1`; проверить владельца перед переносом.
4. Проверить `IExtrusion.SetDirection` и константы направления; для сторон операции изучить `SetSideParameters(self, normal, extrusionType, depth, draftValue, draftOutward, depthObject)`.
5. Константу способа ограничения, допустимость `depthObject` и поведение первой операции брать из справки. `normal` задаёт сторону, `extrusionType` здесь — способ ограничения, не тип операции из `IExtrusions.Add`. Для выреза из нижней XOY в материал Z>0 использовать `SetDirection(c3d.dtReverse)` и `SetSideParameters(False, ...)`; направление и сторона глубины задаются согласованно.
6. Вызвать унаследованный `IModelObject.Update()`, проверить его результат; выполнить `IPart.RebuildModel(redraw)`.
7. Проверить фактические глубину, направление, число тел и габариты через доступные getters. Для выреза проверить изменение геометрии, а не только наличие операции в дереве.

#### Минимальное построение и контроль твёрдого тела

Рабочий вариант для плоского профиля: `GetSketchs().Add()` → `SetPlane(part.GetDefaultObject(c3d.o3d_planeXOY))` → `sketch.Update()` → `BeginEdit(False)` → активный вид фрагмента → `ksapi.IDrawingContainer(view)` → геометрия → `EndEdit()` → выдавливание. Круг внутри внешнего замкнутого контура задаёт сквозное отверстие без отдельного выреза.

Выдавливание: `model.GetExtrusions().Add(c3d.o3d_bossExtrusion)` → `SetProfiles([sketch])` → `SetDirection(c3d.dtNormal)` → `SetSideParameters(True, c3d.etBlind, depth, 0.0, False, None)` → `Update()` → `part.RebuildModel(True)`. Здесь `None` использован для ограничителя при заданной глубине; это не универсальное разрешение для произвольного режима.

Контроль: `ksapi.IFeature(extrusion).GetResultBodies()` возвращает список; проверить число тел, `body.IsSolid()` и `body.GetGabarit(0, 0, 0, 0, 0, 0)`. Последний возвращает `(status, xmin, ymin, zmin, xmax, ymax, zmax)`. `extrusion.GetDepth(True)` проверяет параметр глубины, не наличие выреза в теле. `doc.SaveAs(absolute_path)` возвращает статус. Для размеров и толщины простого выдавливания не требуется исследовать массу и инерцию.

В `examples/basic_part.py` добавлен `verify_cylindrical_walls`: `ksapi.IFeature(part).GetModelObjects([c3d.o3d_face])` → `ksapi.IFace(obj)` → `IsCylinder()` → `GetRadius()` и `GetLimitingEdges()`. Для круговых рёбер `GetMathCurve().GetGabarit(...)` даёт центр, радиус и уровни Z двух границ стенки. Они сопоставляются с ожидаемыми стенками кольца и отверстий, включая глухую глубину; проверка выполняется до сохранения. Это ограниченный контроль простых цилиндров вдоль Z без скруглений и разбиений. Для выреза из нижнего эскиза XOY в материал Z>0 нужна пара `dtReverse` + `SetSideParameters(False, ...)`; `Update=True` не доказывает наличие отверстий. Итоговое тело проверяется через `IFeature(part)`, не через пустой список результата операции выреза. Готовые самостоятельные примеры и JPEG — в [каталоге рецептов](#каталог-готовых-примеров).

#### Кривые: сначала один элемент

- `ICircle` задаёт центр через `SetXc`/`SetYc`, а не `SetX`/`SetY`. Оба набора методов существуют в `ICircle`, но наличие имени не означает нужную семантику параметра центра. Проверка существования имён такую ошибку не обнаружит.
- `IArc.SetDirection(True)` — по часовой стрелке, `False` — против; углы `SetAngle1/SetAngle2` задаются в градусах. Готовая функция с проверкой длины и внутренней точки — [рецепт 17](#17-построить-дугу-с-нужным-направлением). Универсальное сопряжение с обрезкой и ограничения `ICurve2D.CouplingCurveCurve` — рецепт 18; числовой результат этого метода не является готовыми объектами кривых.
- `drawing.GetBeziers().Add()` → `IBezier`. Для открытой составной кубической кривой: `SetClosed(False)`, затем `AddPoint(index, x, y, x_left, y_left, x_right, y_right)` для каждого узла; `left`/`right` — абсолютные координаты управляющих точек. `AddPoint` возвращает кортеж, проверять его статус. После задания узлов — `Update()`.
- Точность аппроксимации Безье зависит от построения управляющих точек и шага, не от одного факта использования Безье.
- При использовании `INurbs.SetNurbsParams` с полюсами, весами и узлами проверить расстояние до расчётных точек на одном коротком участке до генерации всей модели.
- `obj.GetCurve2D().PointOn(parameter, 0, 0)` возвращает статус и координаты; параметры брать из `GetParamMin()`/`GetParamMax()`. `GetDistanceToPoint(x, y)` измеряет расстояние до фактической кривой. Начать с концов и нескольких внутренних точек представительного участка; увеличить выборку только при необходимости.
- Для повторяющегося профиля считать ошибки аппроксимации локально; в API проверить представление одного участка, стыки и итоговое тело. Выборочная проверка — не доказательство максимальной ошибки между точками. Допуск выбирать из задачи и масштаба геометрии, не ужесточать произвольно до нанометров.

#### Сборки

В [§16](#16-вставить-деталь-в-сборку-и-переместить-вхождение) дана цепочка вставки внешней детали: документ `ksDocumentAssembly` → верхний компонент → `GetParts().AddFromFile(...)` → `GetPlacement()` → `UpdatePlacement(True)`. Точка входа сопряжений — `IKompasDocument3D.GetMateConstraints` ([§27](#27-задать-сопряжения-и-ограничить-ход)); перемещение ЛСК не заменяет сопряжение. В обычной правке проверять путь и изменяемое вхождение/сопряжение; полный набор листьев, матриц, ground, слоёв и mates относится к аудиту всей сборки. Движение проверять, когда оно входит в задачу. `UpdatePlacement(True)` может вернуть `False` при применённом переносе: проверять фактическую матрицу и перестроение, не один bool. Это не разрешение игнорировать произвольные ошибки.

### Размерные зависимости эскиза

Следующие методы доступны в нативном KsAPI; **наличие метода не гарантирует нужный результат для произвольного эскиза**.

- `IDrawingObject.NewConstraint()` → `IParametricConstraint`: до `Create()` задать `SetConstraintType`, `SetPartners([...])` и нужные `SetIndex`/`SetPartnerIndex`; после проверить результат и `IsValid()`. Windows-имя `IParametriticConstraint` и одиночный `Partner` не переносить в нативный KsAPI. Для изменения уже созданной связи документация описывает удаление/создание; post-create `SetConstraintValue()` не считать доказанным resize-маршрутом.
- Геометрические связи: `ksCMergePoints`, `ksCHorizontal`, `ksCVertical`, `ksCParallel`, `ksCPerpendicular`, `ksCEqualLength`, `ksCEqualRadius`, `ksCTangentTwoCurves`, `ksCSymmetryTwoPoints`, `ksCConcentricity`. Фиксировать минимальную базу, не все вершины.
- Линейные размеры: `ISymbols2DContainer(view).GetLineDimensions().Add()`, координаты выносных линий, `SetOrientation(ksLinDHorizontal/ksLinDVertical/ksLinDParallel)`, `Update()`. Связь с геометрией — `ksCAssociation`; управляющие связи — `ksCFixedDim` / `ksCDimWithVariable`. Точный порядок создания и индексы требуют проверки. `Associate()` может выбрать не ту совпадающую точку: проверять фактических партнёров и результат изменения.
- Для изменения существующего управляющего размера эскиза использовать `ksapi.IFeature(sketch).GetVariableByName(False, True, name)` **вне `BeginEdit`** → `IVariable.SetExpression(...)` и `SetValue(...)` (возвращают `None`) → `doc3d.CompleteRebuildDocument()`. Проверять фактическую геометрию, состояние solver и ошибки операций; восстановить номинал. `view.GetDimensionVariable(dim)` внутри временного 2D-фрагмента не даёт воспроизводимого изменения геометрии; успешные `UpdateVariables()` и `fragment.CompleteRebuildDocument()` этого не гарантируют. `UpdateVariables()` относится к внешним переменным, не является универсальной заменой solver.
- `IDimensionText.SetNominalValue()` меняет показанный текст, а не геометрию. Декоративная надпись и fully-constrained фиксация не доказывают размерное управление.

Объекты drawing из завершённого `BeginEdit` не использовать в следующем сеансе; вновь получать через ID в актуальном fragment. Пример: [16_dimension_driven_sketch.py](examples/16_dimension_driven_sketch.py).

Справка из Windows-кэша объясняет назначение, но её имена и COM return types не определяют маршалинг нативного KsAPI. Например, локальные `Save()` / `SaveAs(path)` возвращают `res`, хотя Windows-страницы описывают void Automation methods. Ни `SaveAs`, ни `SaveAsToRasterFormat(path, parameters)` не имеют локального per-call overwrite/silent-флага. `IApplication.SetHideMessage()` задаёт глобальные автоматические ответы и может затронуть ссылки/перестроение; не использовать его как обход коллизий файлов. Правила новых выходных путей и владения документами — в разделе [сохранения](#сохранение).

### Запуск и проверка результата

Команда запуска API-сервера не зависит от текущего каталога; пути `scripts/…` ниже указаны относительно каталога скилла. `scripts/run.sh` задаёт `LD_LIBRARY_PATH` и `PYTHONPATH` и запускает `uv run --script`, поэтому макрос напрямую импортирует `ksapi` и константы без правки `sys.path`, а зависимости берутся из PEP 723 в начале файла. Для другой установки заменить путь к `Bin` в команде сервера, а для `scripts/run.sh` задать `KOMPAS_BIN`. Принудительный выбор платформы Qt не требуется.

Сначала подключиться через `GetKompas()` к API-сессии пользователя. Если подключения нет, не запускать новый процесс: показать пользователю полную Bash-команду ниже (не наш `.sh`-файл) или предложить запуск агентом и дождаться явного согласия. Запрос на выполнение макроса не считается согласием на запуск КОМПАС.

```bash
# Команда для пользователя, если API-сессия ещё не запущена:
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
LC_ALL="${LC_ALL:-C.UTF-8}" \
/opt/ascon/kompas3d-v25/Bin/kKompas -APIServer=10500
# При доступной API-сессии — запуск макроса в другом терминале:
bash scripts/run.sh /absolute/path/to/macro.py
```

`run.sh` не запускает КОМПАС самостоятельно. Макросы также должны использовать только `GetKompas()` и завершаться с понятной ошибкой при отсутствии подключения, без перехода к `OpenKompas()`. Не закрывать и не перезапускать процесс пользователя.

Перед исполнением:

1. Если есть ошибка, сомнение или существенный вызов вне рецепта, адресно проверить его сигнатуру, константы и ограничения. Не выполнять `inspect`/`verify` для каждого известного вызова перед пробой.
2. Проверить целевую API-сессию и документ. Создание нового документа не должно изменять чужую активную модель.

После исполнения кратко сообщить результат и существенные ограничения; отдельный протокол этапов нужен для диагностики или регрессии, не для каждого макроса. Проверять статус только у методов с соответствующим возвращаемым значением. Присутствие имени в нативном KsAPI не доказывает отсутствие ошибки в нативной реализации.

### Как читать примеры

- Код работает через нативный `ksapi`. КОМПАС должен быть уже запущен с API; подключение не запускает программу.
- Размеры и координаты — **миллиметры**. Единицы углов указаны отдельно.
- Большинство блоков — части макроса, а не отдельные программы. Перед блоком указано, какие объекты нужны.
- **Проверено в КОМПАС** означает, что описанный пример выполнялся в КОМПАС. Это не обещание для любой формы и любых размеров.
- **Требует проверки** означает, что вызовы известны, но правильный результат в КОМПАС пока не подтверждён.

В коде используются следующие имена:

- `app` — приложение КОМПАС; `doc` — документ, например файл детали или сборки.
- `doc3d` — доступ к 3D-функциям документа; `part` — деталь или верхний компонент сборки.
- `model` — контейнер операций детали; `sketch` — эскиз; `drawing` — геометрия редактируемого эскиза.
- `operation` — операция построения, например выдавливание; `body` — полученное геометрическое тело.
- `component` — **вхождение** детали в сборку. Один файл может быть вставлен несколько раз: это разные вхождения.

`require`, `new_part`, `circle` и другие короткие функции — **наши функции, не методы КОМПАС**. Они находятся в [basic_part.py](examples/basic_part.py). При создании отдельного макроса скопируйте нужные определения в него. Не добавляйте зависимость от расположения скилла или другого проекта.

### Понятия: деталь, сборка, подсборка

**Деталь** — изделие из одного материала без сборочных операций: вал, втулка, крышка. Файл `.m3d`.

**Сборка** — соединённые детали, стандартные изделия и другие сборки. Файл `.a3d`. Их взаимное положение задаётся размещениями и сопряжениями.

**Подсборка** — сборка, вставленная в другую сборку. Например, предварительно собранный редуктор, который затем устанавливают в станок. Это тоже файл `.a3d`.

Такое разделение соответствует ГОСТ 2.101. Не создавайте подсборку только ради совместного скрытия деталей: для этого есть слои (§26).

### 1. Взять основу макроса

[basic_part.py](examples/basic_part.py) — настраиваемая пластина/кольцо с отверстиями. Копируйте нужные функции в самостоятельный макрос; далее показаны отдельные шаги построения. Запуск: `bash scripts/run.sh examples/basic_part.py --help` из каталога скилла.

### 2. Подключиться и создать документ

Этот пример создаёт **временную деталь** и закрывает её без сохранения. Поместите построение внутрь `try`, а сохранение — перед `finally`.

```python
from typing import TypeVar

import ksapi
from constants import constants as c
from constants3d import constants as c3d


T = TypeVar("T")


def require(value: T | None, message: str) -> T:
    if not value:
        raise RuntimeError(message)
    return value


app = require(ksapi.GetKompas(), "Нет запущенной API-сессии КОМПАС")
previous = app.GetActiveDocument()
doc = None
try:
    doc = require(app.GetDocuments().AddWithDefaultSettings(c.ksDocumentPart, True), "Новая деталь")
    doc3d = ksapi.IKompasDocument3D(doc)
    part = require(doc3d.GetTopPart(), "Верхний компонент")
    model = require(part.GetModelContainer(), "Операции детали")
    # Построение и проверка — здесь.
finally:
    if doc:
        require(doc.Close(c.kdDoNotSaveChanges), "Закрытие временной детали")
    if previous:
        previous.SetActive()
```

`require` проверяет результат вызова и выдаёт понятную ошибку. Не применяйте её к методам, которые ничего не возвращают: многие `Set…` возвращают `None` даже при успехе.

Для сборки используйте `c.ksDocumentAssembly`, для чертежа — `c.ksDocumentDrawing`. Для нескольких временных документов удобен список `owned` (§24).

Если `GetKompas()` не подключился, не запускайте и не перезапускайте КОМПАС автоматически. Команда запуска и окружение Python описаны в разделе [подключения](#подключение-без-автоматического-запуска).

### 3. Создать эскиз на базовой плоскости

Нужны `part` и её `model` из §2. Функция `sketch_xoy` из `basic_part.py` создаёт эскиз на XOY, открывает редактирование и обязательно завершает его при выходе из блока.

```python
with sketch_xoy(part, model) as (sketch, drawing):
    rectangle(drawing, -30, -20, 60, 40)

operation = extrude(model, sketch, 10)
```

**Результат:** прямоугольник 60 × 40 мм, выдавленный на 10 мм.

Внутри `sketch_xoy` выполняется последовательность:

1. `model.GetSketchs().Add()` — создать эскиз.
2. `sketch.SetPlane(part.GetDefaultObject(c3d.o3d_planeXOY))` — назначить плоскость.
3. `sketch.Update()`, затем `sketch.BeginEdit(False)` — открыть редактирование.
4. Получить активный вид фрагмента и `ksapi.IDrawingContainer(view)` — доступ к геометрии.
5. В `finally` вызвать `sketch.EndEdit()` — закончить редактирование.

Для XOZ или YOZ замените базовую плоскость и проверьте направление осей. Координаты внутри эскиза не обязательно совпадают с мировыми координатами (§19, §22).

### 4. Нарисовать отрезки и замкнутый контур

Нужен `drawing` открытого эскиза. Функции `line` и `rectangle` берутся из `basic_part.py`.

```python
points = [(0, 0), (40, 0), (30, 20), (0, 20)]
for start, end in zip(points, points[1:] + points[:1]):
    line(drawing, start, end)
```

Последний отрезок соединяет последнюю точку с первой. Для обычного прямоугольника достаточно `rectangle(drawing, x, y, width, height)`.

Прямые вызовы API:

- Отрезок: `GetLineSegments().Add()`, затем `SetX1/SetY1/SetX2/SetY2` и `Update()`.
- Прямоугольник: `GetRectangles().Add()`, затем `SetX/SetY/SetWidth/SetHeight` и `Update()`.
- Многоугольник одним вызовом — §19.

**Проверьте:** контур замкнут, не пересекает себя и не содержит рёбер нулевой длины. Для сложных контуров можно использовать `shapely.Polygon(points).is_valid` и `.area`.

### 5. Нарисовать окружность и отверстие

В открытом эскизе вызовите:

```python
circle(drawing, 0, 0, 25)  # Наружная окружность, радиус 25 мм.
circle(drawing, 0, 0, 5)   # Внутренняя окружность, радиус 5 мм.
```

После выдавливания получится кольцо. Внутренняя замкнутая окружность задаёт отверстие в профиле.

В API центр окружности задаётся через **`SetXc/SetYc`**, а не `SetX/SetY`: `drawing.GetCircles().Add()` → центр → `SetRadius` → `Update()`.

Для отверстия в уже существующем теле создайте отдельный эскиз и вырез (§6). Окружности не должны касаться друг друга или внешнего контура. Наличие окружности в эскизе ещё не доказывает наличие отверстия в теле — проверьте результат.

### 6. Выдавить профиль или сделать вырез

Нужны `model` и **завершённый** эскиз `sketch`. Задайте положительную глубину `depth` в мм и `cut`: `False` для добавления материала, `True` для выреза.

```python
kind = c3d.o3d_cutExtrusion if cut else c3d.o3d_bossExtrusion
operation = require(model.GetExtrusions().Add(kind), "Выдавливание")
operation.SetProfiles([sketch])
# В этом рецепте эскиз на нижней XOY, материал расположен в Z>0.
operation.SetDirection(c3d.dtReverse if cut else c3d.dtNormal)
require(operation.SetSideParameters(not cut, c3d.etBlind, depth, 0.0, False, None), "Глубина")
require(operation.Update(), "Построение")
```

В готовой функции это `extrude(model, sketch, depth, cut=False)`.

- `True/False` в `SetSideParameters` выбирает прямую/обратную сторону. Направление и сторона должны соответствовать друг другу.
- Для выреза из нижней XOY в материал Z>0 используйте пару `dtReverse` + `SetSideParameters(False, ...)`, не `dtNormal`. Успешный статус операции не доказывает наличие отверстий.
- `etBlind` — ограничение числовой глубиной; `0.0` — нулевой уклон.
- `None` — нет объекта, ограничивающего глубину в этом режиме.
- `SetProfiles` принимает список эскизов и возвращает `None`.

**Проверьте:** тело появилось с нужной стороны; вырез действительно удалил материал. Для сквозного отверстия в простой пластине из примера глубина равна её толщине. Это не универсальный режим «через всё»; не подменяйте его произвольно большим числом.

### 7. Повторить окружности в одном эскизе

Для нескольких одинаковых отверстий проще нарисовать все окружности в одном эскизе и сделать один вырез.

**По окружности.** Нужны `count` — число отверстий, `pitch_radius` — радиус расположения центров, `hole_radius` — радиус отверстия.

```python
import math

for i in range(count):
    angle = 2 * math.pi * i / count
    circle(drawing, pitch_radius * math.cos(angle), pitch_radius * math.sin(angle), hole_radius)
```

**По сетке.** Нужны число строк/столбцов `rows`, `cols`, начало `x0`, `y0`, шаги `step_x`, `step_y` и `hole_radius`.

```python
for row in range(rows):
    for col in range(cols):
        circle(drawing, x0 + col * step_x, y0 + row * step_y, hole_radius)
```

Выберите один рисунок. Проверьте, что отверстия не пересекаются и не выходят за материал. Для повторения самой операции или отдельных тел используйте §15.

### 8. Построить гладкую кривую Безье

Функция `bezier(drawing, nodes)` принимает узлы вида `(x, y, x_left, y_left, x_right, y_right)`. Последние четыре числа — **абсолютные координаты** управляющих точек, не смещения от узла.

Если известны функция кривой `p(t)` и её производная `d(t)`, один кубический участок между `t0` и `t1` можно приблизить так:

```python
h = (t1 - t0) / 3
p0, p3 = p(t0), p(t1)
p1 = p0 + h * d(t0)
p2 = p3 - h * d(t1)
```

Здесь `p(t)` и `d(t)` возвращают массивы `numpy`; для кортежей нужны покоординатные вычисления. `p0/p3` — концы, `p1/p2` — управляющие точки.

API: `GetBeziers().Add()` → `SetClosed(False)` → `AddPoint(index, x, y, x_left, y_left, x_right, y_right)` → `Update()`. `AddPoint` возвращает кортеж: проверяйте **первый элемент**, а не истинность всего кортежа.

**Проверьте сначала один участок:** концы, стыки и несколько внутренних точек. Для фактической кривой доступны `GetCurve2D().GetDistanceToPoint(x,y)` и `PointOn(parameter,0,0)`; границы параметра — `GetParamMin/Max`. Выборка точек не доказывает точность между ними. NURBS из другой библиотеки нельзя переносить без проверки полюсов, весов и узлов.

### 9. Проверить и сохранить результат

Для простого выдавливания готовые функции — `solid_bounds(part, operation)` и `save_new(doc, path)` из `basic_part.py`.

Габариты тела читаются через `body.GetGabarit(0,0,0,0,0,0)`. Возврат: `(status, xmin, ymin, zmin, xmax, ymax, zmax)`. Размер по каждой оси — разность максимума и минимума.

Для конечного результата обычно нужен `ksapi.IFeature(part).GetResultBodies()`. Список тел отдельной операции может быть пустым или содержать только новые копии (§15, §21).

`verify_cylindrical_walls(part, expected)` проверяет простые цилиндрические стенки вдоль Z, без скруглений и разбиений. Запись: `(x, y, radius, zmin, zmax)`.

**Сохранение:** `doc.SaveAs(absolute_path)` возвращает статус. Проверьте, что появился непустой файл. `save_new` дополнительно запрещает перезапись существующего файла. Для уже открытого рабочего файла есть `doc.Save()`.

Сохраняйте только принятый результат. Если важно доказать сохранность, откройте проверочную копию и повторите проверки. `SaveAs` не собирает внешние файлы в переносимый комплект. Экспорт и изображения не обязательны после каждой правки (§30).

### 13. Создать эскиз на смещённой плоскости

Пример: плоскость на Z=15 мм и цилиндр Ø10 высотой 5 мм. Нужны собственная `part`, её `model` и функции `require`, `circle`, `extrude`.

```python
aux = ksapi.IAuxiliaryGeomContainer(part)
plane = require(aux.GetPlanes3D().Add(c3d.o3d_planeOffset), "Плоскость")
offset = ksapi.IPlane3DByOffset(plane)
offset.SetBasePlane(part.GetDefaultObject(c3d.o3d_planeXOY))
offset.SetOffset(15.0)
offset.SetDirection(True)
require(offset.Update(), "Смещение плоскости")

require(sketch.Update(), "Опора эскиза")
fragment = require(sketch.BeginEdit(False), "Редактирование эскиза")
try:
    view = fragment.GetViewsAndLayersManager().GetViews().GetActiveView()
    drawing = ksapi.IDrawingContainer(view)

finally:
    require(sketch.EndEdit(), "Завершение эскиза")

```

**Результат:** одно тело, габариты `(-5, -5, 15, 5, 5, 20)`.

### 14. Сделать фаску или скругление

Самостоятельные сценарии: [11_fillet_edit.py](examples/11_fillet_edit.py) — четыре вертикальных угла пластины, R3 → R5 на том же признаке; [12_chamfer.py](examples/12_chamfer.py) — фаски 2 × 2 мм на тех же четырёх углах. См. [каталог примеров](#каталог-готовых-примеров).

Нужны `model` и `edges` — список **выбранных** рёбер. Получить кандидатов можно через `ksapi.IFeature(base).GetModelObjects([c3d.o3d_edge])`, где `base` — исходная операция. Выбирайте рёбра по положению и геометрии, не просто `edges[0]`.

**Фаска 1 × 1 мм:**

```python
chamfer = require(model.GetChamfers().Add(), "Фаска")
chamfer.SetBaseObjects(edges)
chamfer.SetBuildingType(c3d.ksChamferTwoSides)
chamfer.SetDistance1(1.0)
chamfer.SetDistance2(1.0)
chamfer.SetTangent(False)
require(chamfer.Update(), "Фаска")
```

**Скругление R1 — отдельный пример, не продолжение фаски:**

```python
fillet = require(model.GetFillets().Add(), "Скругление")
fillet.SetBaseObjects(edges)
fillet.SetBuildingType(c3d.ksFilletCircleArc)
fillet.SetRadius1(1.0)
fillet.SetTangent(False)
require(fillet.Update(), "Скругление")
```

`SetBaseObjects` принимает список. В примерах рёбра выбираются по обоим концам: X=±30, Y=±20, Z=0…10; индекс ребра не используется. После изменения формы получайте топологию заново; конечные тела читайте у **детали**, не у операции.

**Правка живого скругления:** перечитать `model.GetFillets().GetFillet(0)` в собственной детали с единственным скруглением → `SetRadius1(5)` → `Update()` → проверить новые грани. Не пересоздавать признак и не править API5 definition вместо живого API7-объекта.

В `11_fillet_edit.py` проверяются четыре четверти цилиндра: радиус, площадь и диапазоны координат у каждого угла. Ось каждой поверхности параллельна Z и отстоит на R от двух исходных боковых плоскостей. Ожидаемый объём: `60*40*10 - 4*(1-pi/4)*R**2*10`.

В `12_chamfer.py` проверяются вершины и площадь каждой диагональной плоской грани; объём `24000 - 4*(2*2/2)*10 = 23920` мм³. Вместе эти проверки отличают реальное снятие материала от успешного `Update()` без нужной геометрии. Ограничение кэша МЦХ разобрано в начале файла.

### 15. Повторить тела или операции

#### Прямоугольный массив операций

[15_linear_pattern.py](examples/15_linear_pattern.py) создаёт пластину 60 × 40 × 10, один сквозной вырез Ø4 с центром (−20,−10), затем размножает **операцию**, не рисует ещё пять окружностей.

Маршрут: `model.GetFeaturePatterns().Add(c3d.o3d_meshCopy)` → `ksapi.ILinearPattern(feature)` → `SetInitialObjects([seed])` → оси `SetAxis1(OX)`, `SetAxis2(OY)` → шаги 20/20 → количества 3/2 → `SetBuildingType(c.ksLPSaveAll)` → `Update()`. В коде также явно заданы направления и режим шага между соседними экземплярами.

`Count1/Count2` включают исходный экземпляр. Не устанавливайте `Angle2=0`: штатные 90° сохраняют две независимые оси, а нулевой угол может свести сетку в линию.

Проверяются **все шесть стенок** Ø4 на Z=0…10, центры `X=(-20,0,20)`, `Y=(-10,10)`, объём `24000 - 6*pi*2**2*10`. Совпадения счётчиков недостаточно. Этот пример относится к прямоугольной сетке на плоской пластине, не к произвольным криволинейным массивам.

#### Круговой массив отдельных тел

Нужны `part`, `model` и отдельное тело `body`. Пример делает четыре экземпляра с шагом 90° вокруг OZ; исходное тело должно находиться в стороне от оси.

```python
feature = require(model.GetFeaturePatterns().Add(c3d.o3d_BodiesCircularCopy), "Массив тел")
pattern = ksapi.ICircularPattern(feature)
pattern.SetInitialObjects([body])
pattern.SetAxis(part.GetDefaultObject(c3d.o3d_axisOZ))
pattern.SetBuildingType(c3d.ksCPSaveAll)
pattern.SetCount1(1)
pattern.SetCount2(4)
pattern.SetStep2(90.0)
pattern.SetBoundaryInstancesStepFactor2(False)
pattern.SetSaveInitialOrientation(False)
require(pattern.Update(), "Построение массива")
```

Для четырёх цилиндров на R10 ожидаемые центры — `(±10,0)` и `(0,±10)`. Угол — градусы. `Count1/Step1` относятся к радиальному направлению, `Count2/Step2` — к обходу окружности. При `BoundaryInstancesStepFactor2=False` шаг — между соседними экземплярами.

Для этого массива `GetResultBodies()` содержит **три новые копии**, исходное тело учитывается отдельно. Проверяйте все конечные тела детали.

Для оси на пересечении двух плоскостей: `aux.GetAxes3D().Add(c3d.o3d_axis2Planes)` → `ksapi.IAxis3DBy2Planes(axis)` → `SetPlane1/SetPlane2` → `Update()`.

#### Круговой массив операций — требует отдельной проверки

Если `seed` — операция выреза, цепочка настройки такая:

```python
feature = require(model.GetFeaturePatterns().Add(c3d.o3d_circularCopy), "Массив операций")
pattern = ksapi.ICircularPattern(feature)
pattern.SetInitialObjects([seed])
pattern.SetGeometryPattern(False)
pattern.SetAxis(part.GetDefaultObject(c3d.o3d_axisOZ))
pattern.SetBuildingType(c3d.ksCPSaveAll)
pattern.SetCount1(1)
pattern.SetStep1(0.0)
pattern.SetCount2(4)
pattern.SetBoundaryInstancesStepFactor2(False)
pattern.SetStep2(90.0)
pattern.SetStepByAxis(0.0)
pattern.SetReverseDirection(False)
pattern.SetSaveInitialOrientation(False)
require(pattern.Update(), "Массив операций")
```

`GetExemplarsCounts(0,0)` возвращает `(status,count1,count2)`, но дополнительно нужно проверить сами отверстия.

Для сложных тел проверяйте сначала две копии, затем небольшой массив и только потом нужное количество. Успех маленькой пробы не гарантирует успех большого массива или последующего объединения.

### 16. Вставить деталь в сборку и переместить вхождение

Нужны открытая сборка `doc`, путь детали `component_path` и `require`. Для новой сборки документ создаётся как в §2 с типом `c.ksDocumentAssembly`.

```python
from pathlib import Path

source = Path(component_path).expanduser().resolve(strict=True)
require(source.is_file() and source.suffix.lower() == ".m3d", "Нужен файл детали")
assembly = ksapi.IKompasDocument3D(doc).GetTopPart()
parts = assembly.GetParts()
before = parts.GetCount()
component = require(parts.AddFromFile(str(source), True, True), "Вставка детали")
require(parts.GetCount() == before + 1, "Число вхождений")
```

В `AddFromFile(fileName, externalFile, redraw)` первый `True` сохраняет внешнюю ссылку, второй запрашивает перерисовку. Исходный файл должен оставаться доступным. Вставка не создаёт сопряжений.

**Перенос на X=30 мм.** Нужен свободный от сопряжений компонент; проверьте его фиксацию. В существующем механизме положение обычно меняют через сопряжения (§27), а не принудительный перенос.

```python
expected = list(component.GetPlacement().GetMatrix3D())
expected[12:15] = [30.0, 0.0, 0.0]
require(component.GetPlacement().SetOrigin(30.0, 0.0, 0.0), "Перенос")
update_ok = component.UpdatePlacement(True)
require(assembly.RebuildModel(True), "Перестроение сборки")
actual = list(component.GetPlacement().GetMatrix3D())
require(len(actual) == len(expected), "Размер матрицы")
require(all(abs(a - b) < 1e-6 for a, b in zip(actual, expected)), "Положение и ориентация")
print("UpdatePlacement:", update_ok)
```

`UpdatePlacement(True)` может вернуть `False` при применённом переносе, поэтому проверяйте фактическую матрицу и результат перестроения. При несовпадении остановитесь, не повторяйте перенос вслепую. Для существующей сборки дополнительно сравните остальные вхождения, фиксацию и сопряжения (§28).

### 17. Построить дугу с нужным направлением

Нужны `drawing` и функция `arc` из `basic_part.py`.

```python
import math

# Дуга от 350° до 10° против часовой стрелки: размах 20°.
obj = arc(drawing, (10, 20), 5, math.radians(350), math.radians(10))
```

Функция принимает **радианы**, а API `SetAngle1/SetAngle2` — **градусы**. `IArc.SetDirection(True)` означает по часовой стрелке, `False` — против. Центр задаётся `SetXc/SetYc`.

Функция проверяет длину дуги и её начало, середину и конец. Одних концов недостаточно: у малой и дополняющей дуг они совпадают. Для полной окружности используйте `circle`, а не одинаковые начальный и конечный углы.

Размах против часовой стрелки — `(a2-a1) % math.tau`, по часовой — `(a1-a2) % math.tau`. Длина — `radius * sweep`.

### 18. Соединить два участка касательной дугой

#### Готовый случай: два отрезка

`blend_lines(p0, corner, p1, radius)` из `basic_part.py` рассчитывает обрезку ломаной и вставку дуги. Она **только считает координаты**, не меняет КОМПАС.

Для ломаной `(0,0) → (10,0) → (10,10)` и радиуса 2 мм:

```python
segment_a, arc_params, segment_b = blend_lines((0, 0), (10, 0), (10, 10), 2)
center, radius, a1, a2, clockwise = arc_params
line(drawing, *segment_a)
arc(drawing, center, radius, a1, a2, clockwise=clockwise)
line(drawing, *segment_b)
```

Получатся отрезки `(0,0) → (8,0)` и `(10,2) → (10,10)`, между ними дуга R2 с центром `(8,2)`. Код рисует итоговый контур в новом эскизе; при правке старого нужно отдельно заменить исходные отрезки.

Функция не продолжает линии и отвергает радиус, при котором не остаётся двух ненулевых отрезков. Длина обрезки от угла — `radius * tan(abs(turn)/2)`, где `turn` — угол поворота.
#### Произвольные кривые — алгоритм, не готовая функция

Для кривых `A(t)` и `B(u)`:

1. Задайте радиус, стороны сопряжения и разрешённые интервалы. Не продолжайте кривые без требования задачи.
2. Для единичной левой нормали `N=(-dy,dx)/hypot(dx,dy)` решите уравнение `A(t)+side_a*r*N_a(t) = B(u)+side_b*r*N_b(u)`, где стороны равны −1 или +1.
3. Проверьте найденные точки касания, радиус, сторону и допустимые интервалы. Численному решателю недостаточно вернуть `success`; нужна проверка невязки в мм.
4. Обрежьте исходные участки и вставьте дугу с согласованным направлением. Безье делится алгоритмом де Кастельжо, NURBS — корректным разбиением по узлам; простая перестановка конца меняет форму.
5. Проверьте концы, касательные и отсутствие самопересечений. Линейный и угловой допуски задаются отдельно.

Метод требует ненулевых производных; несколько начальных приближений не гарантируют поиск всех решений. Радиус и конструкцию перехода определяет инженерная задача. Например, круговая галтель ножки зуба не равнозначна профилю обкатки.

**Не использовать как готовое сопряжение:** `curve_a.CouplingCurveCurve(curve_b, radius)` существует, но возвращает список чисел, не готовую дугу. Формат списка и обрезка исходных кривых не установлены — не угадывайте индексы и не используйте его как готовое сопряжение.

### 19. Создать отдельные тела, объединить их или построить по сечениям

Нужны объекты одной детали.

Режимы результата операции: `ksOperationUnion=0`, `ksOperationNewBody=1`, `ksOperationCut=2`, `ksOperationIntersect=3`.

```python
boolean = require(model.GetBooleans().Add(), "Булева операция")
```

### 20. Построить спираль и протянуть по ней профиль

Нужны `part`, её `model`, базовая плоскость `base_plane`, радиус `radius`, шаг `pitch`, число витков `turns` и замкнутый эскиз `profile`. Длины — мм. Для описанного случая спираль начинается на +X, а профиль лежит в радиально-осевой плоскости XOZ.

```python
aux = ksapi.IAuxiliaryGeomContainer(part)
spiral = require(aux.GetSpirals3D().Add(c3d.o3d_cylindricSpiral), "Спираль")
parameters = ksapi.ICylindricSpiral3D(spiral)
parameters.SetBasePlane(base_plane)
parameters.SetBasePoint(0, 0)
parameters.SetDiameter(2 * radius)
parameters.SetBuildingType(c3d.ksSBTByStepAndTurnCount)
parameters.SetStep(pitch)
parameters.SetTurnsCount(turns)
parameters.SetBuildingDirection(True)
parameters.SetTurnDirection(True)
parameters.SetTurningAngle(0)  # Градусы.
require(parameters.Update(), "Построение спирали")

operation = require(model.GetEvolutions().Add(c3d.o3d_bossEvolution), "Кинематическая операция")
operation.SetSketch(profile)
operation.SetEdges([spiral])
operation.SetOperationResult(c3d.ksOperationNewBody)
operation.SetSketchShiftType(c3d.ksEvShiftKeepAngle)
require(operation.Update(), "Профиль вдоль спирали")
```

`ksEvShiftParallel=0` сохраняет параллельность профиля, `ksEvShiftKeepAngle=1` — угол с направляющей, `ksEvShiftOrtogonal=2` ставит профиль по нормали.

Для образца с профилем по радиусам 9,5…10,5 мм, шагом 1 мм и тремя витками ожидаемые габариты — ±10,5 мм и Z=−0,3…3,3 мм. Для пружины отдельно проверьте опорную плоскость (§25), для резьбы — форму и посадку. Короткая спираль не доказывает пригодность длинной резьбы.

### 21. Повернуть и перенести тело внутри детали

Это меняет **геометрию детали**, а не положение её вхождения в сборке. Для сборки используйте §16 или §27.

Нужны `model`, тело `body`, угол `angle` в радианах и перенос `tx`, `ty`, `tz` в мм.

```python
import math

co, si = math.cos(angle), math.sin(angle)
matrix = [co, si, 0, 0, -si, co, 0, 0, 0, 0, 1, 0, tx, ty, tz, 1]
operation = require(model.GetBodyRepositions().Add(), "Перенос тела")
operation.SetRepositionBody(body)
operation.SetCopyBody(False)
operation.GetPosition().InitByMatrix3D(matrix)
require(operation.Update(), "Преобразование тела")
```

**Результат:** призма 4×2×3 мм после поворота +90° вокруг Z и переноса `(10,20,30)` имеет габариты `(8,20,30)…(10,24,33)`.

У этой операции `GetResultBodies()` может быть пустым даже после преобразования тела. Проверяйте конечные тела через `ksapi.IFeature(part).GetResultBodies()` и их габариты. Не переносите это объяснение на любую неудачную операцию.

### 22. Не перепутать направление смещения плоскости

Имя XOZ или YOZ не говорит, куда направлена её нормаль. Из-за этого положительное расстояние может дать смещение не в ту мировую сторону.

1. Прочитайте начало и две оси пробного эскиза на базовой плоскости (§19).
2. Вычислите единичную нормаль: векторное произведение осей, делённое на его длину.
3. Для плоскости, перпендикулярной мировой оси `axis`, используйте `SetOffset(abs(offset))` и `SetDirection(offset * normal[axis] > 0)`.
4. Прочитайте начало полученного эскиза и проверьте направление будущего выреза.

`offset` здесь — разность целевой и исходной координаты в мм. Для произвольно наклонённой плоскости сначала вычислите подписанное расстояние вдоль её нормали, а не мировую координату.

Не выбирайте направление только по `offset > 0`: учитывайте нормаль базовой плоскости, иначе возможно зеркальное смещение радиальных отверстий. Для произвольных наклонов проверяйте полученное положение эскиза.

### 23. Разобраться с ошибкой булевой операции

Ошибка 5 («объект не найден») **не обязательно означает потерянную ссылку на тело**. Она может возникать и при касании инструмента с уже существующим отверстием.

Для простых тел результаты `body.CheckIntersectionWithBody(other, True)` трактуются так:

- `[]` — тела раздельны;
- `[3]` — внешнее касание;
- `[4]` — объёмное пересечение, вложение или совпадение.

Это не полный справочник всех кодов. Для вычитания нужен удаляемый объём. Если инструмент доказанно не пересекает материал, повтор той же операции ничего не исправит.

Ненужное вспомогательное тело удаляется через `ksapi.ISurfaceContainer(part).GetBodySurfaceRemovers().Add()` → `SetDeletingObjects([tool])` → `Update()`. Скрыть тело недостаточно: оно останется в геометрии.

При объединении сложных совпадающих торцов можно использовать общий цилиндрический сердечник внутри исходной формы: одна половина + сердечник, затем другая. Это допустимо только если сердечник не добавляет материал за заданную оболочку. Полностью вложенный заполнитель может быть лишней операцией.

#### Ускорить повторные вырезы

Создайте один инструмент или минимальную группу, размножьте тела (§15), затем вычтите исходники и копии одной булевой операцией. Непересекающиеся инструменты передаются списком в `SetInitialObjects`; объединять их заранее не нужно.
#### Импортировать сложную деталь, если пользователь разрешил STEP

Сначала проверьте `documents.GetItemByFilePath(absolute_source_step)`: уже открытый чужой документ не меняйте ради импорта. Для своего документа используйте `documents.Open(absolute_source_step, True, True)`, сразу зарегистрируйте его в `owned`, проверьте тела/форму и сохраните в новый `.m3d`. Закройте свой документ в `finally`.

Импортированное тело без эскизов — не нативное параметрическое построение. Сохраняйте отметку `imported_geometry=True` и `source_step`. Если STEP уже в мировых координатах, не переносите его повторно. Не переходите к импорту автоматически после ошибки.

### 24. Закрыть только свои временные документы

`owned` — обычный Python-список документов, созданных или открытых **этим запуском**. Это не свойство КОМПАС.

```python
owned = []
try:
    doc, part, model = new_part(app, "Временная деталь", owned=owned)
    # Построение, проверка, при необходимости сохранение.
finally:
    close_owned(owned)
```

`new_part` регистрирует документ сразу после создания, до получения `part`. Это позволяет закрыть его даже при ошибке подготовки.

`close_owned` из `basic_part.py` делает следующее:

```python
def close_owned(owned: list[ksapi.IKompasDocument]) -> None:
    while owned:
        doc = owned[-1]
        require(doc.Close(c.kdDoNotSaveChanges), "Закрытие собственного документа")
        owned.pop()
```

Закрытие идёт в обратном порядке, **без сохранения новых изменений**. Ранее сохранённый файл остаётся на диске. Это уборка временных документов, не Undo.

Уже открытые документы пользователя в список не добавляются. Название «Деталь без имени» не доказывает, что документ ваш. После обрыва API не продолжайте вызовы закрытия вслепую.

Для перечисления документов используется `documents.GetItem(i)` с индексами **от 1 до Count**: `range(1, documents.GetCount()+1)`. Сначала получите список, потом закрывайте свои документы — не меняйте коллекцию во время индексного обхода. Путь документа — `GetFullPath()`, не `GetPathName`.

### 25. Проверить ошибки дерева и опору эскиза

Для обычной правки начните с `GetObjectError()` затронутой операции. Полный обход нужен для регрессии, неясной ошибки/сломанных зависимостей или явно запрошенного аудита, а не после каждого изменения. `Update=True`, успешное перестроение и одно тело не означают, что все операции исправны.

Готовая функция `feature_errors(part)` из `basic_part.py` обходит полное дерево, включая скрытые эскизы. Для самостоятельного обхода нужны `ksapi.IFeature(obj).GetObjectError()` и рекурсивный `GetSubFeatures(c.ksOperTree, True, True)`. Пропускайте пустые ссылки и уже посещённые `reference`. В ошибке полезны путь элемента, тип, код и состояние.

`GetState()` — набор флагов, не код ошибки: `0x8` — зависимость от ЛСК, `0x100` — недоопределённый эскиз, `0x200` — определённый, `0x2` — нужно перестроение, `0x2000` — фиксация компонента. Ненулевое значение само по себе не ошибка.

Код `GetObjectError()==54` означает «Неизвестная ошибка». У эскиза проверьте опорную плоскость: `sketch.GetPlane()` не должен возвращать `None`. Это одна из возможных причин, не универсальная расшифровка кода 54.

#### Эскизу с собственной системой координат всё равно нужна плоскость

Одного `sketch.SetCoordinateSystem(lcs)` недостаточно. Перед первым обновлением и редактированием:

1. Создайте три точки `origin`, `origin+u`, `origin+v`, где `u/v` — независимые направления плоскости. API: `model.GetPoints3D().Add()`, `SetX/SetY/SetZ`, `Update()`.
2. Создайте плоскость: `aux.GetPlanes3D().Add(c3d.o3d_plane3Points)` → `ksapi.IPlane3DBy3Points(plane)` → `SetPoint1/2/3` → `Update()`.
3. Назначьте эскизу и `SetPlane(plane)`, и `SetCoordinateSystem(lcs)`.

Точки и плоскость можно скрыть, но не удалять. Для спирали с началом на +X касательная равна `(0,R,pitch/(2*pi))`; с ней согласуется нормаль круглого профиля пружины.

Не считайте позднее назначение плоскости готовым ремонтом уже ошибочного эскиза; после правки проверьте его состояние и зависимые операции.

### 26. Скрыть группу деталей, не меняя структуру сборки

Для совместного скрытия используйте слой, а не искусственную подсборку. Нужны `doc` и выбранные вхождения `components`.

```python
manager = ksapi.IKompasDocument3D(doc).GetDocument3DManager()
layers = manager.GetLayers3D()
layer = layers.GetLayer3DByName("Опоры")
if not layer:
    layer = require(layers.Add(), "Новый слой")
    layer.SetName("Опоры")
layer.SetVisible(True)
require(layer.Update(), "Слой")
for component in components:
    component.SetLayerNumber(layer.GetNumber())
    component.Update()
manager.Update()
```

Для скрытия — `layer.SetVisible(False)`, затем `layer.Update()` и `manager.Update()`; для показа — `True`. `component.GetVisibleState()` не обязательно отражает скрытие через слой; проверяйте и слой, и вид сборки.

Менеджер получайте через `GetDocument3DManager()`, не прямым приведением `IDocument3DManager(doc)`. `PartsGroupNumber` — группировка позиций спецификации, не видимость; для совместного скрытия используйте слои, не пользовательские папки.

Меняйте иерархию только ради реальной структуры монтажа. Для разворачивания подсборки нужно сохранить мировые размещения, ссылки, цвета, фиксацию, слои и сопряжения; при неединичных размещениях родителя/детей требуется композиция матриц. Удаляется вставка через `IFeature(instance).Delete()`, а не файлы деталей. Подсчёт деталей должен рекурсивно считать конечные детали, не только верхние узлы.

Не используйте `AddFromFile(..., externalFile=False)`, `CreateDocument('', c.ksDocumentAssembly, True, True)` или `MoveParts=True` как готовый способ создания подсборки: они не гарантируют требуемый тип документа и дерево сборки.

### 27. Задать сопряжения и ограничить ход

Сопряжение задаёт связь между вхождениями: соосность, совпадение плоскостей, расстояние, параллельность.
Нужны `doc`, выбранные объекты `base1/base2`, тип `kind`, ориентация `alignment` и значение `value` в единицах этого типа.

```python
mates = ksapi.IKompasDocument3D(doc).GetMateConstraints()
mate = require(mates.Add(kind), "Сопряжение")
mate.SetBaseObject1(base1)
mate.SetBaseObject2(base2)
mate.SetFixed(c3d.ksMFixedPart1)
mate.SetAlignment(alignment)
mate.SetParamValue(value)
require(mate.Update(), "Применение сопряжения")
require(ksapi.IFeature(mate).GetObjectError() == 0, "Ошибка сопряжения")
```

Типы: `c3d.mc_Concentric`, `mc_Coincidence`, `mc_Distance`, `mc_Parallel`. Расстояния — мм; единицы угла смотрите для конкретного типа.

**Не путайте два вида фиксации:** `mate.SetFixed(ksMFixedPart1)` выбирает сохраняемую сторону решения; `component.SetFixed(True)` закрепляет само вхождение в сборке. Для подвижного вхождения — `False`, проверка — `IsFixed()`.

Выбирайте поверхности по форме, размеру и назначению, не по номеру грани. Они доступны через `ksapi.IModelContainer(component).GetObjects(c3d.o3d_face)`. Для общей исходной системы координат можно использовать базовые плоскости `GetDefaultObject(o3d_planeXOY/XOZ/YOZ)`.

#### Проверить, куда переместил детали решатель

Чистое дерево не гарантирует правильного положения. После сопряжения сравните положение затронутых вхождений с ожидаемым; если меняется ориентация, учитывайте полную матрицу, не только перенос. Не требуется обходить все неизменившиеся вхождения сборки. Для расстояния `abs(z2-z1)` может выбрать неверную сторону. У внутренних цилиндров направление параметрической оси не определяет нужное выравнивание; для выбора ближайшего положения доступно `c3d.ksMCAlignmentClosest`. Проверяйте фактическое положение.

Для совпадающих физических торцов учитывайте ориентацию граней; общие исходные XY-базы подходят только деталям, действительно построенным в общей системе координат. Три независимых сонаправленных совпадения XY/XZ/YZ могут задать жёсткую связь, но это связь технологических баз, не модель физических контактов.

Соосность + торец оставляют вращение; параллельность поперечной плоскости запрещает проворот. Лишние упоры с обеих сторон могут переопределить механизм.

#### Ограничить осевой ход

Нужны сопряжение расстояния `distance_mate` и границы `min_value/max_value` в мм.

```python
interval = ksapi.IMateInterval(distance_mate)
interval.SetUseInterval(True)
require(interval.SetValueRange(min_value, max_value), "Границы хода")
require(distance_mate.Update(), "Применение интервала")
require(abs(interval.GetMinValue() - min_value) < 1e-6, "Нижняя граница")
require(abs(interval.GetMaxValue() - max_value) < 1e-6, "Верхняя граница")
```

**Сначала включите интервал, затем задайте диапазон.** Обратный порядок может оставить границы `0..0` без ошибки дерева. Не фиксируйте обе стороны, если решатель должен переместить одну из них.

Проверяйте реальный ход и запрещённые перемещения на копии.

После удаления сопряжений в коллекции возможны пустые места — пропускайте `None`. Не полагайтесь на сохранность заданного через `SetName` имени сопряжения; перед поиском по имени проверьте его чтением. Сопряжения не создают автоматически передачу вращения, винтовую связь, упругость или контактную динамику.

#### Тонкость выбора поверхности

Для цилиндрической поверхности с угловым первым параметром `GetMathSurface().GetPoint(0,0)` и `GetPoint(pi,0)` дают противоположные точки; их среднее лежит на оси. Если второй параметр направлен вдоль оси, разность `GetPoint(0,1)-GetPoint(0,0)` задаёт её направление. `pi` — радианы. Перед применением проверьте параметризацию поверхности.

Математическую нормаль плоскости читайте через `GetMathSurface().GetNormal`. Для ориентации физического торца отдельно учитывайте топологическую `IFace.GetNormal(0,0)`; не отождествляйте параметры её вызова с параметрами точки математической поверхности. Не навязывайте выравнивание по параметрическим осям без проверки ориентации физических граней.

### 28. Изменить существующую сборку без пересоздания

Перед правкой коротко запишите: **что добавить, изменить, удалить и сохранить неизменным**.

1. Найдите документ по полному пути (§10). Не создавайте новую сборку вместо существующей и не переоткрывайте несохранённый документ пользователя.
2. Снимите только состояние, нужное для правки: для цвета — прежний цвет, для переноса — матрицу вхождения и влияющие сопряжения, для замены детали — источник и затронутые связи. Полный снимок сборки для локального изменения не нужен.
3. Выберите минимальную правку. Цвет — только свойства отображения; видимость — слой; положение — размещение или параметр сопряжения; размер — параметр существующей операции.
4. Измените выбранные объекты. Не вставляйте заново остальные детали и не пересоздавайте все сопряжения.
5. Перестройте зависимую часть и проверьте как изменение, так и то, что должно было остаться прежним.
6. Сохраните проверенный результат. Если важна сохранность ссылок и параметров на диске, проверьте повторное открытие копии.

`RebuildModel(True)` обновляет существующую модель. Это не то же самое, что удалить сборку и построить её заново.

При изменении формы могут исчезнуть прежние грани и рёбра. Заново получите нужные поверхности и исправьте только затронутые сопряжения. Универсальная замена детали с автоматическим сохранением всех связей не подтверждена; не подменяйте её незаметным удалением и повторной вставкой.

`reference` действует в текущей сессии, не является постоянным идентификатором после открытия файла. Различайте вхождения по пути в дереве и источнику; одного имени или индекса недостаточно.

В КОМПАС записывает **один процесс**. Независимые расчёты можно выполнять отдельно, но передавайте им зафиксированные входные данные и версию задачи; устаревший результат не применяйте. Undo — [раздел Undo](#undo), повторное использование проверок — §30.

### 30. Не повторять неизменившуюся работу

Отдельно учитывайте **форму детали**, **положение в сборке**, **внешний вид** и **результаты проверок**. Изменение цвета не требует заново строить геометрию; перенос детали требует перепроверить сборочные зазоры, но не обязательно локальную форму детали.

**Чтобы повторно использовать результат, нужно знать, из чего он получен.** Запишите параметры, исходные файлы, версию кода/SDK и зависимости. Для автоматической проверки можно вычислять хеш содержимого. Наличие файла и время его изменения сами по себе не доказывают актуальность.

У проверки тоже есть условия: форма, положение, область, единицы, допуски и версия алгоритма. После изменения этих условий старый результат проверки нельзя считать актуальным.

Для дорогих проверок зазоров сначала используйте расчётные ограничения и габаритные коробки в общей системе координат, затем точную проверку нужных пар поверхностей. Быстрое отсечение должно быть консервативным. Несколько проверенных положений не доказывают отсутствие столкновений на всём ходе. Не импортируйте повторно неизменную геометрию только ради её размеров.

**Контрольное сохранение** — проверенная версия, к которой можно вернуться. Для длительного процесса храните путь, версию входных данных и последний успешный этап. Хеширование и замеры времени нужны для автоматического reuse и оптимизации, не для каждой ручной правки. Если делаете benchmark, отдельно измеряйте построение/правку, перестроение, проверку, сохранение и экспорт. Сравнивайте одинаковую правку одной исходной модели с одинаковыми проверками; число операций не равно времени.

Экспорт STEP/STL, сетка и рендер нужны только как отдельный запрошенный результат, после проверки CAD. Для нового массового экспорта сначала проверьте два разных компонента: геометрию, единицы, соответствие вхождениям и ориентацию. Не угадывайте соответствие по порядку объектов. Сетку можно сохранить, если форма и настройки разбиения не изменились; положение и цвет обновляются отдельно.

Переносимый комплект требует всех внешних зависимостей. Проверьте его открытие из нового расположения без старых путей: один `SaveAs` этого не обеспечивает. Не выдавайте промежуточный или устаревший результат за окончательный.

### 31. Родное отверстие, а не окружность-вырез

[13_native_hole.py](examples/13_native_hole.py) делает **Holes3D** в пластине 60 × 40 × 10: Ø10, глубина 6, плоское дно, центр (12,7), вход с верхней грани Z=10. В дереве сохраняются диаметр, глубина и опорная поверхность родной операции.

Основная цепочка:

1. Найти верхнюю плоскую грань по геометрии, не по номеру.
2. `model.GetHoles3D().Add()`; `SetHoleType(c3d.ksHTBase)`, `SetDiameter(10)`, `SetDepthType(c3d.ksDTValue)`, `SetDepth(6)`, `SetEndFaceType(c3d.ksEFFlat)`.
3. Через `ksapi.IHoleDisposal(hole)` назначить `SetBaseSurface(face)`, `SetPerpendicular(True)`, `SetOffsetType(c3d.ksOffsetByCoords)`.
4. Получить `disposal.GetPoint3DParamSurface()`, задать `SetOffset1/SetOffset2` и `SetSurfaceObject(face)`, затем `hole.Update()`.

Координаты точки поверхности относятся к её параметризации; нельзя переносить `(12,7)` на произвольную грань как гарантированные мировые XY.

`SetSurfaceObject(base)` в этом примере может вернуть `False` при построенном отверстии. Выводите этот статус и принимайте результат только после проверки геометрии. Это не основание игнорировать `False` у других методов.

Режимы «через всё», цековка, зенковка и резьба требуют собственных примеров и геометрических проверок; успешное простое глухое отверстие не подтверждает остальные режимы.

### 32. Оболочка: коробка с открытым верхом

[14_shell.py](examples/14_shell.py) выдавливает блок 60 × 40 × 20, удаляет верхнюю грань Z=20 и делает стенку 2 мм **внутрь**. Это родной `IShell`, не булево вычитание второго блока.

Маршрут: найти верхнюю грань по положению → `model.GetShells().Add()` → `SetDeletedFaces([top_face], False)` → `SetThinType(c3d.dtReverse)` → `SetThickness(2)` → `Update()`. Второй аргумент `SetDeletedFaces` управляет включением касательных граней. Для оболочки этот `dtReverse` означает внутрь; не переносите семантику направления выреза на другую операцию.

Наверху остаётся плоский ободок — это нормально, он не закрывает коробку.

### 33. Выбрать грань или окружность по геометрии

[geometric_selection.py](examples/geometric_selection.py) — самостоятельный пример: скопировать в макрос только нужные функции, не импортировать скилл как библиотеку. Селекторы не меняют модель и не запускают CAD; запуск примера создаёт и закрывает только свою временную деталь. Нужны `part` и **текущее результирующее тело** `body`; принадлежность объектов телу проверяется через `GetBody()`. После rebuild/Undo/reopen заново получить тело и вызвать селектор, не хранить прежние topology references.

- `select_plane(part, body, point=..., normal=..., length_tol=..., angle_tol=...)`: плоская грань с нормалью, параллельной заданной, и опорной плоскостью через `point`. Сравниваются нормализованные направления и расстояние до плоскости. **Не проверяет попадание точки внутрь обрезанного контура**; несколько копланарных граней — неоднозначность, а не право выбрать первую.
- `select_circle(part, body, center=..., radius=..., normal=..., length_tol=..., angle_tol=...)`: целое круговое ребро по центру, радиусу и нормали плоскости. Дуги и эллипсы исключены. Центр/радиус читаются из `IMathCurve3D`, не вычисляются по bounding box.
- `select_cylinder(part, body, radius=..., axis_point=..., axis=..., span=(t0, t1), length_tol=..., angle_tol=...)`: радиус, направление и положение осевой прямой, затем осевая протяжённость ограниченной грани. `span` задаётся в мм от `axis_point` вдоль нормализованного **заданного** `axis`; при смене знака оси меняются знаки/порядок интервала. Не путать диапазон вдоль оси с мировыми Z.

Начало и ось аналитической поверхности/окружности читаются через `GetPlacement().GetOrigin(...)` и `GetVector(c3d.o3d_axisOZ, ...)`. Нормаль/ось сравниваются **без знака**: `n` и `−n` эквивалентны; это не выбор внешней стороны тела. Координаты должны быть в одной системе детали; размещения вхождений сборки автоматически не применяются.

Допуски **обязательны**: `length_tol` — положительное расстояние в мм для координат/радиусов; `angle_tol` — угловое отклонение в радианах. Значения `1e-5` мм и `1e-7` рад в примере относятся к его аналитической геометрии, а не являются универсальным производственным допуском. Проверяются статусы выходных кортежей, конечность чисел и ненулевые направления; ошибка чтения не маскируется пропуском кандидата.

Ноль или несколько совпадений дают `ValueError` с запросом, количеством совпадений и измеренными признаками кандидатов. Нет выбора по индексу, ближайшему объекту или автоматического расширения допуска. Для уточнения ограничить тело/геометрические признаки под задачу.

**Граница цилиндрического рецепта:** протяжённость читается по полным круговым торцам, перпендикулярным оси, и концам прямых швов. Подходящий по опорному цилиндру кандидат с дуговой/сплайновой или иной неподдерживаемой обрезкой останавливает выбор: нужен отдельный маршрут точного анализа границ, не подмена мировым AABB или выборкой точек. Совпадение опорного цилиндра и осевого диапазона не доказывает полноту стенки, отсутствие разрывов или назначение «отверстие»; это выбор объекта, не общий валидатор топологии.

### 34. Диагностический указатель: симптом → действие

Читать только ветку наблюдаемой ошибки; это не обязательный checklist построения.

- **Грань/ребро недоступны после rebuild, Undo или reopen:** получить текущие тела и повторить геометрический выбор (§33). Старый `reference` не постоянный ID; затронутые зависимости — §28, Undo — [раздел Undo](#undo).
- **Нет совпадения или совпадений несколько:** прочитать признаки кандидатов, проверить тело, систему координат, радиус, осевую прямую и диапазон (§33). Уточнить запрос; не брать первый индекс и не увеличивать допуск вслепую.
- **Setter/Update прошёл, но форма прежняя или другая:** проверить фактическую затронутую геометрию и применимость режима. Для глубины проверить сторону операции (§6), для управляющего размера — [маршрут через `IFeature`](#размерные-зависимости-эскиза); не подбирать цепочки rebuild. `None` у setter не ошибка, `True` не доказательство формы.
- **Вызов оборвался или не завершился, результат неизвестен:** остановить новые записи; сохранить последний этап/traceback, проверить документ и возможную модальность после восстановления доступа. Не повторять запись и не делать автоматический Undo ([Undo](#undo)); правила модальных диалогов — [сохранение без диалогов](#сохранение).

Если неизвестно имя/маршалинг конкретного метода — адресный `sdk.py inspect`/`page` из раздела [документации и сигнатур API](#документация-и-сигнатуры-api), не повторное исследование всех уже известных операций.
