# КОМПАС-3D: нативный KsAPI

Использовать нативный Python KsAPI установленного КОМПАС-3D, без COM и `pywin32`. Примеры адаптированы под v25 в Linux. Скилл автономен: нужны Python 3, `uv`, Bash и КОМПАС. Справка готовится офлайн из установленного SDK; при переносе скилла переносить и подготовленный кэш. Новые пакеты макросов могут требовать сеть, подготовка SDK — нет.

## Рабочий подход

Цель — построить или изменить модель. **По умолчанию сразу адаптировать подходящий готовый пример и выполнять, а не начинать с исследования SDK.** Для знакомых операций не перечитывать несколько примеров и не перепроверять уже показанные в них методы. SDK открывать адресно только для конкретного отсутствующего вызова, неоднозначной сигнатуры или фактической ошибки; после ответа возвращаться к построению.

1. Подключиться через `ksapi.GetKompas()` к существующей API-сессии. Нужный документ найти по **абсолютному пути** через `GetDocuments().GetItemByFilePath(path)`; только если он не открыт — `Open`. Проверить тип и `GetFullPath()`. Уже открытый документ не переоткрывать, не заменять дисковой версией и не закрывать. Для новой модели создать собственный документ.
2. Выбрать дерево новой детали или минимальную правку существующей: **параметр → эскиз → операция → вхождение → сопряжения**. Не пересоздавать модель ради одного изменения. Перед сложной правкой сохранить только нужное исходное состояние.
3. Написать/адаптировать макрос из одного подходящего примера или раздела [рецептов](references/recipes.md). Известный рабочий маршрут не исследовать заново. Если нужного вызова нет — адресно уточнить его в SDK, не расширяя поиск на остальные уже известные операции. Простая смена размеров обычно обходится без отдельной пробы; проверки из `validate` выбирать под задачу.
4. Проверить новый код через `ast.parse` и выполнить в CAD. **Один процесс пишет в КОМПАС**; собственные временные документы и редактирование эскиза закрывать в `finally`. После смены топологии/Undo заново получать используемые грани. У выходных кортежей проверять статус; setters могут возвращать `None`.
5. Обновить затронутую модель, проверить нужный результат и сохранить в абсолютный путь, если это входит в задачу. Не перезаписывать чужие файлы без основания; достаточно статуса сохранения и наличия файла, **без обязательного reopen**. Сообщить результат и закончить.

Для знакомой операции обычно достаточно рабочего кода. Примеры полезны при выборе реализации, локальная обёртка и SDK — при вопросах о сигнатуре, поведении или ошибке. Читать столько, сколько помогает следующему действию, без обязательного обхода всех источников. Рискованный неизвестный режим сначала опробовать в собственном временном документе; после обрыва API не повторять запись вслепую.

## Как спланировать модель детали

**От общего к частному:** разобрать форму → выбрать основание и базы → построить основной объём → добавить/удалить материал → повторить элементы → обработать края. Это методика выбора дерева, не единственный правильный порядок. Для существующей модели сохранить её замысел и изменить нужную ветвь, а не проектировать всё заново.

Перед кодом кратко определить:

1. **Геометрия и назначение.** Выделить основные объёмы, отверстия, пазы, посадки и симметрии. По чертежу учитывать виды, разрезы и размеры; не угадывать скрытую форму по одной проекции. Существенные недостающие размеры уточнять, допустимые предположения обозначать.
2. **Основание.** Выбрать конструктивно главный элемент, от которого удобно добавлять/вычитать материал и задавать остальные размеры. Самый крупный объём — частый, но не обязательный выбор.
3. **Базы и ориентация.** Разместить начало координат, главную ось и плоскость первого эскиза по симметрии, монтажным/измерительным базам и удобству дальнейших операций. Предпочитать устойчивые базовые/смещённые плоскости и оси; грань использовать, когда нужна именно связь с ней. Не опирать важные элементы на случайные рёбра скруглений.
4. **Замысел изменений (design intent).** Решить, что должно оставаться соосным, симметричным, равноудалённым или на заданном расстоянии от края. Отверстие «по центру» и «в 10 мм от края» — разные зависимости. По возможности определять эскизы размерами и геометрическими связями без переопределения. Python-переменная и координаты, вычисленные генератором, сами по себе не создают редактируемую зависимость внутри КОМПАС; не выдавать их за полную параметризацию.
5. **Основной объём и конструктивные элементы.** Выбрать операции по форме ниже; затем добавить выступы, рёбра, отверстия и вырезы. Разделять элементы по смыслу и будущим изменениям, а не объединять всё в один сложный эскиз ради меньшего числа операций.
6. **Повторения и завершение.** Использовать массивы/зеркало для конструктивно связанных повторов. Мелкие фаски и скругления обычно делать поздно, чтобы не усложнять опоры. Оболочку, уклоны и формообразующие скругления ставить там, где они правильно задают толщину и переходы; правило «все скругления в конце» не абсолютное.
7. **Результат.** Проверить успешность построения и один итоговый признак, например объём из условия. Само требование параметрической модели не означает обязательного теста изменения размеров; он нужен только по отдельному запросу или при диагностике.

### Как выбрать операцию

- Постоянное сечение вдоль прямой — **выдавливание**; осесимметричный профиль — **вращение**.
- Карман, паз, простой вырез — **вырез выдавливанием**; кольцевая канавка — **вырез вращением**. Для отверстия с собственными параметрами/типом — родная операция **Holes3D** (§31 рецептов).
- Профиль вдоль траектории — **кинематическая операция**; переход между несколькими профилями — **элемент по сечениям**.
- Регулярный повтор — **массив операций**; симметричный элемент — **зеркало**. Повтор тел выбирать только когда нужны отдельные тела, не вместо массива отверстий.
- Тонкостенная полость — **оболочка**; скосы и плавные переходы краёв — **фаски/скругления**.

Для нетривиальной новой детали достаточно одной строки предполагаемого дерева, без отдельного документа и согласования каждого шага. Например, фланец: **вращение ступенчатого профиля (основание + ступица) → центральное отверстие → одно крепёжное отверстие → круговой массив → фаски**. Два выдавливания вместо вращения тоже допустимы: выбирать по удобству размеров и редактирования, не минимизировать число операций любой ценой. Для простой правки отдельный план не нужен.

Выбор операции — геометрический ориентир, не подтверждение всех режимов Linux API. Использовать известную реализацию; если её нет — нужный пример. [Справка о параметризации эскиза](https://help.ascon.ru/KOMPAS/25/ru-RU/cm_make_sketch.html) — дополнительный источник, не обязательное чтение.

## Размерная модель, а не замороженный чертёж

Если требуется параметрическая редактируемая модель, задавать конструктивные зависимости **внутри КОМПАС**: совпадение концов, горизонтальность/вертикальность, касательность, равенство, симметрию и управляющие размеры. Фиксировать только необходимую базу; не фиксировать оба конца каждого отрезка ради `WellConstrained`. Нулевые степени свободы, Python-переменные и точные начальные координаты не доказывают сохранение замысла при редактировании. Декоративный размер без управляющей связи тоже не доказательство. `IDimensionText.SetNominalValue()` меняет отображаемый текст, а не геометрию; не использовать его как механизм параметрического изменения.

Параметрическую модель строить с нативными связями и размерами, но **не добавлять пробные изменения размеров в каждое решение**. Тест изменения/восстановления нужен только по отдельному запросу на проверку редактируемости или при диагностике конкретной проблемы. Тогда менять нативный размер и проверять фактическую геометрию; перегенерация профиля Python-кодом не считается этим тестом. Неудачу API не маскировать тотальной фиксацией. Не заявлять проведённый тест редактируемости, если его не выполняли.

Проверенный общий пример: [16_dimension_driven_sketch.py](examples/16_dimension_driven_sketch.py), [маршрут API и границы квалификации](references/ksapi.md#размерные-зависимости-эскиза-доступность-и-квалификация). Существующий размер менять **вне `BeginEdit`**: `ksapi.IFeature(sketch).GetVariableByName(False, True, name)` → `SetExpression(...)` и `SetValue(...)` → `doc3d.CompleteRebuildDocument()` → проверить B-rep. На Linux v25 изменение через `view.GetDimensionVariable(dim)` временного 2D-фрагмента оказалось невоспроизводимым: значение меняется, геометрия иногда нет даже при успешных rebuild. `UpdateVariables()` применяет внешние переменные, не является универсальным solver-вызовом. Новый маршрут прошёл линейное/радиальное изменение и восстановление на десяти новых деталях 1.1 подряд и на копии сохранённой модели. Объекты drawing после нового `BeginEdit` получать заново через `fragment.GetObjectById(id)`. Наличие переменной с новым значением без изменения геометрии не считать успехом. Это правило одинаково для линейных и радиальных размеров: не возвращаться к старому маршруту через fragment и не подбирать цепочки rebuild. При отказе проверенного маршрута сохранить текущую деталь и сообщить конкретное расхождение, а не переключаться на другой размер ради успешного теста.

## Координаты эскиза и направление операции

Не отождествлять имена плоскостей с привычной экранной ориентацией. Для незнакомой опоры получить `ISketch.GetPoint3D(u, v, 0, 0, 0)` для `(0,0)`, `(1,0)`, `(0,1)`, проверить статус каждого выходного кортежа и вывести локальные оси/нормаль. Для наклонной грани использовать проекцию и обратное преобразование. Это короткая проверка системы координат, не повод строить отдельную пробную деталь для каждого знакомого эскиза.

Направление операции и активная сторона глубины — разные настройки: при обратном направлении настраивать соответствующую сторону `SetSideParameters(False, ...)`. Для нового маршрута подтвердить вход, дно/выход по реальным поверхностям; `Update()` и значение глубины в setter не доказывают сквозной вырез. Не делать обязательным `GetSideParameters()`, если его output-marshalling не работает в текущей обёртке: это ограничение binding, а не основание пропустить геометрическую проверку.

## Проверки по риску, а не по списку

**Обычное решение задачи:** достаточно успешного построения, отсутствия ошибок операций и сравнения объёма с эталоном, если он дан. Не добавлять обход граней/рёбер/вершин, аудит связей размеров, проверку всех габаритов, пробные изменения размеров и повторное открытие файла. Для локальной правки проверить только её результат. Проверять по завершении логического действия, а не после каждого setter.

**Расширенные проверки полезны**, когда есть неизвестный маршрут API, существенно другая геометрия, ошибка/подозрительный результат, смена топологии с зависимостями или требование к посадке/движению. Проверять именно затронутые поверхности, связи или зазор. При известной неоднозначности bool из рецепта читать фактический результат; это не разрешение игнорировать произвольные ошибки. Успешный `Update()` сам по себе не доказывает нужную форму.

**Регрессия рецептов:** подробные `validate` и `run_examples.py` предназначены для разработки примеров и повторной квалификации. Расчёт объёма, полный аудит, save/reopen и испытание всего хода обычно избыточны для локальной правки, но могут быть полезны для диагностики или приёмки. Проверку повторного открытия выполнять на собственной копии.

Проверки соразмерять задаче; неизменившиеся части обычно не требуют повторных измерений. Экспорт, рендер и замеры производительности добавлять, когда они нужны для результата. Защита пользовательских документов и безопасность Undo сохраняются независимо от объёма проверок.

### Что именно доказано

Разделять **геометрию**, **замысел/редактируемость**, **сохранение** и **визуальное представление**. Подтверждение одной категории не засчитывать за остальные. Контрольный объём — независимая проверка после чтения размеров, не целевая функция подбора недостающей геометрии. Совпадение CAD с формулой из той же ошибочной интерпретации не доказывает соответствие чертежу; при расхождении не объявлять PDF ошибочным без доказательств. Округлённый эталон сравнивать с интервалом его точности, не с произвольным процентным допуском. Состояния «не проверено», «не прошло», «прошло с оговоркой» не объединять в успех. Сообщения «операция создана», «геометрия проверена», «эталон совпал» и «файл сохранён» выводить только после соответствующего успешного действия, не заранее в helper построения. Долгий незавершённый вызов — «ожидается», а не доказанное зависание; при подозрении на модальность остановить новые записи и сначала получить свидетельства.

Проверять геометрический смысл, а не случайное число граней/рёбер: отверстие после пересечений может иметь несколько соосных цилиндрических участков и дуг вместо двух целых окружностей. Использовать радиус, ось, границы глубины, совокупную протяжённость и непрерывность. Объединённого bounding box недостаточно для доказательства отсутствия зазоров; длина без проверки плоскости/радиуса тоже недостаточна. Узкий validator простого цилиндра не переносить на произвольную топологию.

После булева объединения соседние копланарные участки могут стать одной непрямоугольной гранью. Не ожидать отдельной грани на каждый смысловой элемент: её bounding box может включать соседний участок. При расхождении сначала прочитать контур и проверить характерные вершины/рёбра, а не менять правильную модель или просто ослаблять допуск.

Если нужен preview, оркестратор экспортирует его нативно из уже построенного документа/сохранённой модели, открывает и проверяет видимость существенных деталей, фактический формат и размеры. Ради другого ракурса/экспорта не повторять построение, параметрические тесты и МЦХ. Запрос разрешения/масштаба не равен полученному разрешению. Проверку валидности JPEG выполнять библиотекой только когда требуется, не дублировать во всех макросах собственный парсер SOF.

## Сохранение без диалогов перезаписи

- **Новая модель:** до создания документа проверить все выходы (`.m3d`/`.a3d`, preview и зависимости); непосредственно перед `SaveAs`/экспортом повторить проверку отсутствия. Каждой попытке выделять новый каталог, например через `tempfile.mkdtemp`; не переиспользовать путь предыдущего прогона. Нельзя заранее создавать пустой целевой файл: CAD увидит существующий путь.
- **Правка уже сохранённого собственного документа:** проверить абсолютный `GetFullPath()` и использовать `Save()`, не `SaveAs()` в тот же существующий файл. Право изменять пользовательский документ должно следовать из задачи, не из одного совпадения имени.
- **Повторный экспорт:** новый путь/каталог; прежнее изображение не удалять и не перезаписывать автоматически. Сначала проверить все выходы, чтобы не получить сохранённую модель и заблокированный запросом preview.
- Не удалять существующий файл ради обхода диалога и не отключать глобально предупреждения приложения. Если модальный диалог уже возник или вызов не завершился и исход неизвестен, не запускать второй CAD-писатель, не повторять запись вслепую и не нажимать «Да» автоматически: установить последнее действие и владельца целевого файла, сообщить блокировку. Отсутствие вызова, который *должен* показать диалог, не доказывает отсутствие любых диалогов в сессии.

## Разделение работы при делегировании

- **Исполнитель:** прочитать переданные условие и готовое изображение, написать самостоятельный `.py`, построить, проверить и сохранить нативную модель. Вернуть пути и фактический результат проверок. Не извлекать/обрезать картинки из PDF, не готовить preview, не подбирать ракурс и не писать время выполнения в коде или отчёте.
- **Оркестратор:** подготовить входные markdown/JPG до передачи задания; при необходимости измерить время; после результата подготовить и проверить preview из готовой модели отдельным действием. Пока исполнитель работает в CAD, оркестратор не пишет туда параллельно. Не запускать решающий скрипт заново только ради изображения.
- В решении отделять построение/проверку/сохранение от представления: обычный запуск сохраняет модель без обязательного растрового экспорта и библиотек обработки изображений.

## Честный повторяемый прогон — только когда запрошен

Оркестратор фиксирует версию скилла и одинаковый критерий готовности **до** серии; не улучшает его по ходу решения тестов. Подготовку исходников учитывает отдельно. Полное время измеряет сам от передачи задания до проверенной сохранённой модели и просмотренного preview; если включает собственную подготовку — явно указывает начало интервала. Не поручать исполнителю хронометраж и не требовать временных меток в решении. Ожидания, ошибки, помощь и продолжения не вычитать; время моделирования и последующего preview различать. Неполный или неизвестный интервал так и назвать; техническое время CAD не подменяет время решения.

Один свежий контекст на задачу, один CAD-писатель, задачи последовательно. Исполнителю передавать только текущий исходник, замороженный общий скилл и собственный каталог. Старые ответы, журналы, трейсы, историю git и решения других тестов не использовать даже «как пример API». Архив вне активного скилла уменьшает утечку, но **не является файловой песочницей**; без реального ограничения доступа не заявлять техническую изоляцию. В сравнение включать неуспехи, помощь, ограничения редактируемости и отсутствующие проверки; ускорение при другом критерии качества не выдавать за чистое улучшение производительности. Сохранять ID запуска и критерии/свидетельства отдельно от решающего контекста.

## Что сохранять при адаптации

- **Нативное редактируемое дерево:** строить через KsAPI, не заменять эскизы/операции генерацией OpenSCAD/OCP → STEP. Импорт — только по запросу/согласованному исключению, явно отмечать его; успешные нативные детали не подменять. STEP/STL и изображения — только как запрошенный результат; изображение получать из КОМПАС.
- **Выбор объектов:** вхождения различать по пути/идентификатору, функциональные грани — по геометрии и назначению, не только имени или индексу. Сессионный `reference` не является постоянным ID после открытия файла.
- **Монтажная структура (ГОСТ 2.101):** деталь `.m3d`, сборка/подсборка `.a3d`. Подсборка — реально предварительно собираемая группа, не папка для скрытия; для видимости использовать слои (§26). При замене детали адресно проверить затронутые сопряжения, не пересоздавать все.
- **Копии и ссылки:** для пробы связанной детали копировать файл до открытия; это не снимок dirty-документа. При модальном запросе переназначения ссылок от `SaveAs` остановить API и попросить оставить ссылки без изменения. `SaveAs` — не транзакция и не упаковка зависимостей (§24, §30).
- **Дорогие вычисления и reuse — если нужны:** один владелец расчёта, фиксированные входы; устаревший результат не применять. При автоматическом кэшировании учитывать содержимое и параметры, не только наличие файла. Не заводить систему хешей, benchmark или отдельный фреймворк ради простой правки (§30).

Рецепты: понятия деталь/сборка/подсборка — раздел «Понятия»; основа/подключение/эскиз — §1–3; контуры/выдавливание — §4–6; повтор координат/Безье — §7–8; контроль/существующий документ/2D — §9–11; вращение/смещённая плоскость — §12–13; фаска/скругление/feature-массив/сборка — §14–16; дуга `IArc`/касательное сопряжение с обрезкой — §17–18; монтажная структура — §26; сборочные сопряжения, знаки расстояний и ограниченный осевой ход — §27; **итеративная правка, проверки/reuse и Undo — [§§28–30](references/recipes.md)**. Родное отверстие Holes3D — §31; открытая коробка оболочкой IShell — §32. В каталоге есть самостоятельные примеры 11–15 с аналитическим объёмом и проверками положения поверхностей. Статус проверки смотреть в выбранном разделе: заготовку не выдавать за выполненное построение.

При ошибке, подозрительной геометрии или конкретном неизвестном вызове — адресная диагностика ниже. Не перестраивать всю модель ради исправления, которое можно проверить на одном элементе. Выборка точек не доказывает непрерывную точность кривой.

## Краткий контракт Undo

- Группа Undo — **один документ**, не multi-doc/save transaction. До группы проверить целевой active document/frame, `IsEnableUndo()` и `IsUndoContainer()`; доступность Undo/Redo проверять перед самой командой, не до первой правки. Не захватывать чужую уже открытую группу. `SetUndoContainer`/`SetEnableUndo` возвращают `None`: состояние проверять через `Is…`, не `assert setter()`.
- Закрыть собственную группу в `finally` — **не rollback**; exception не отменяет изменения. Пустая группа не разрешает Undo предыдущей пользовательской операции. Явный Undo допустим только для известной завершённой изменяющей группы и квалифицированного сценария; после неизвестного исхода вызова/обрыва — inspection, не автоматический Undo.
- Проверенный синхронный маршрут: `doc.GetDocumentFrame().ExecuteKompasCommand(c.ksCMEditUndo, False)` / `c.ksCMEditRedo`; команды **57643 / 57644**, не `prUndo/prRedo`. До вызова — `IsKompasCommandEnable`; после — геометрический readback и свежие topology references. Не очищать и не отключать пользовательскую историю по умолчанию (`ClearUndo()` возвращает bool).
- Live Linux v25: **4 scratch-part сценария passed**, подтверждены одиночная и групповая геометрическая Undo/Redo, отсутствие автоматического отката при exception и сохранение предыдущей истории пустой группой. Последующая live-проверка простой сборки подтвердила **4 сценария Undo/Redo**: группа переносов вхождения, создание трёх mates, группа изменений расстояния с перемещением детали, удаление mate. Проверены полные матрицы, ground, параметры/базы mates и дерево. `UpdatePlacement(True)` возвращал `False` при применённом переносе: результат доказан readback + rebuild, не одним bool. Это не квалификация произвольной сборки, смены topology или нескольких документов (§27, §29). Подробности: [ksapi](references/ksapi.md), [§§28–30](references/recipes.md) и [scratch demo](examples/incremental_edit.py).

## Подключение: без автоматического запуска

**Использовать только `ksapi.GetKompas()` для подключения к уже запущенной пользователем API-сессии.** Если подключения нет — остановиться и дать полную Bash-команду ниже либо предложить запуск агентом и дождаться явного согласия. Запрос на построение модели или запуск макроса сам по себе не разрешает запуск КОМПАС. Не подменять подключение вызовом `OpenKompas()`.

```bash
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
LC_ALL="${LC_ALL:-C.UTF-8}" \
/opt/ascon/kompas3d-v25/Bin/kKompas -APIServer=10500
```

Пользователю давать полную команду, не наш `.sh`-файл; для другой установки заменить абсолютные пути. Не добавлять `-hidden`: окно должно быть видно. Обычное окно из меню не обязательно является API-сессией. Не закрывать и не перезапускать пользовательский процесс. `scripts/launch-api.sh` — только для согласованного запуска агентом; порт сервера не перенастраивает клиент `GetKompas()`.

## Макрос: uv и PEP 723

Новый макрос должен быть самостоятельным: копировать нужные функции примера, не импортировать их из каталога скилла. В начале объявить только используемые зависимости:

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["numpy", "scipy"]
# ///

import ksapi
import numpy as np
from scipy.optimize import root_scalar
```

Для простой геометрии достаточно `dependencies = []`. `numpy` — координаты и вращения; `scipy` — сплайны и численные решения; `shapely` — проверка плоских контуров; `cadquery-ocp` (импорт `OCP`) — независимый B-rep/STEP-контроль, только если нужен. `ksapi` и константы поставляются с КОМПАС, не устанавливать их из PyPI. Не писать условные импорты, не создавать проект/`.venv` и не запускать `pip install` ради одного макроса.

```bash
LD_LIBRARY_PATH="/opt/ascon/kompas3d-v25/Bin${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
PYTHONPATH="/opt/ascon/kompas3d-v25/Bin${PYTHONPATH:+:$PYTHONPATH}" \
uv run --script /absolute/path/to/main.py аргументы
```

`uv run --script main.py` и `uv run main.py` обрабатывают PEP 723, **`uv run python main.py` — нет**. Первый запуск новых пакетов может требовать сеть; следующие используют кэш. Необязательный `bash scripts/run.sh /absolute/path/to/main.py аргументы` задаёт то же окружение, сохраняет текущий каталог и не запускает КОМПАС. Это не песочница.

## Адресная диагностика

Команды выполнять из каталога скилла либо использовать абсолютные пути к скриптам:

```bash
# Один пакет нужных методов, один разбор обёртки.
python3 scripts/sdk.py inspect ISketch.BeginEdit IExtrusion.SetSideParameters --source
# Сначала найти имя; затем отфильтровать нужные методы интерфейса.
python3 scripts/sdk.py local 'Bezier' --limit 15
python3 scripts/sdk.py inspect IExtrusion --match 'side'
python3 scripts/sdk.py constants 'плоскость XOY'
python3 scripts/sdk.py search 'IExtrusions Add' --limit 3
python3 scripts/sdk.py page IExtrusions.Add ISketch.BeginEdit
python3 scripts/sdk.py toc ISketch
python3 scripts/sdk.py links ISketch.BeginEdit
# verify проверяет только наличие символов, не корректность макроса.
python3 scripts/sdk.py verify --brief ISketch.BeginEdit IExtrusion.SetSideParameters
```

- Пакетировать `inspect` и `page`, не запускать shell-цикл по одному методу. `--source` применять к конкретным методам, не ко всему большому интерфейсу. Ошибочное имя не скрывает остальные результаты, но даёт код `1`; исправлять только его. Независимые запросы не связывать через `&&`.
- При аварийном обрыве нативного соединения остановить запись: результат последнего вызова неизвестен. Не повторять макрос вслепую и не перезапускать CAD; сохранить traceback/последний этап и сообщить пользователю. После восстановления сначала проверить состояние документа.
- `sdk.py` читает обёртку через AST, не импортирует `ksapi` и не запускает КОМПАС. Наличие метода не доказывает семантику или работоспособность. `ksapi.IInterface(obj)` запрашивает другой интерфейс того же объекта, не дочерний объект.
- Установка по умолчанию: `/opt/ascon/kompas3d-v25/Bin`; другая — `KOMPAS_BIN` или `sdk.py --bin /path/to/Bin`. Глобальные `--bin`/`--docs` ставить перед подкомандой.
- Если нужна справка и индекса нет, подготовить его в исходном репозитории через `uv run --script prepare/prepare_docs.py` с окружением KsAPI из [справочника](references/ksapi.md#подготовка-базы-документации), затем при необходимости перенести кэш со скиллом. База хранится в `.cache/kompas-sdk-docs`; другой путь — `KOMPAS_SDK_DOCS` или `sdk.py --docs /path/to/docs`. Подготовка из локального SDK не использует сеть.
- Поиск индексированный, требует всех слов/префиксов, по умолчанию раздел **KsAPI**; `--section api7`, `api5`, `any` выбираются явно. `page` принимает символ (`ISketch.BeginEdit`), ID или полный ключ страницы; неоднозначность — ошибка. `toc` показывает родителей/детей, `links` — переходы. `local`/`search`/`toc`/`links` поддерживают `--limit`, `--offset`, `next_offset`. Локальная обёртка определяет доступные Python-вызовы и маршалинг.

## Совместно с text-to-cad

Необязательное дополнение — [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad): `cad` — постановка задачи и проверка геометрии; `dfm` — технологичность; `dfam-check` — проверки для аддитивного производства; `step-parts` — поиск стандартных и покупных деталей; `engineering-drawing` — оформление чертежей. Обращаться к установленному дополнительному скиллу для соответствующей отдельной задачи, не перед каждым построением через KsAPI. Ссылка сама по себе не устанавливает и не загружает скиллы; установка описана в [upstream README](https://github.com/earthtojake/text-to-cad#install).

**Разделять рекомендации и backend:** инженерные требования, допуски и методики проверки брать из подходящего дополнительного скилла; создание и изменение `.m3d`/`.a3d`, API-сессию, сохранение и изображения выполнять по этому скиллу через KsAPI. Маршрут `cadgen/build123d → STEP`, внешний viewer и автоматические mesh-экспорты из `cad` не подменяют нативное дерево КОМПАС и не включаются без соответствующего запроса. Стандартную деталь из STEP считать явно импортированным компонентом, а не нативной параметрической деталью. Не запускать установку, MCP-сервер, viewer или производственное оборудование только из-за этой ссылки.\
